## ITB How the Barrier Works

> **Security notice.** ITB is an experimental symmetric cipher construction without prior peer review, independent cryptanalysis, or formal certification. The construction's security properties have **not been verified** by independent cryptographers or mathematicians.
>
> PRF-grade hash functions are **required**. No warranty is provided.

**No bespoke cryptography.** ITB composes established, standardized primitives rather than introducing new cryptographic designs. Security properties and regulatory status are inherited from the underlying primitives; see [README.md](README.md) for jurisdictional certification details.

## 1. The Core Idea: Absorption

The shipped construction composes two inseparable mechanisms — a per-chunk 48-bit keyed permutation (Rank Barrier) and a per-pixel absorption stage (Pixel Barrier), described in detail in §12. This section outlines the absorption intuition provided by the Pixel Barrier.

The hash output is computed and determines the pixel configuration, but it is absorbed into a random container. The observer sees only: random byte ± modification. Because the original random byte is unknown, the modification is unknown, making the hash output unobservable.

This is not encryption layered on top, but absorption — the random container fully absorbs the hash output. Like dropping a drop of paint into an ocean of random waves, the paint is present, but an observer sees only waves.

Under passive observation, this property is computation-model-independent: no amount of computational power can extract information that is not present in the observation.

**Formal basis:** `∀v, ∀h : ∃(c, d) : embed(c, h, d) = v` — for every observed byte value and every possible hash output, there exists a container byte and data configuration that produces that exact observation (see [Proof 1](PROOFS.md#proof-1-information-theoretic-barrier), [SCIENCE.md § 2.1 Theorem 1](SCIENCE.md#21-information-theoretic-barrier-theorem-1), and [SECURITY.md § 4](SECURITY.md#4-information-theoretic-barrier-metrics)).

## 2. Two Independent Sources of Randomness

The barrier relies on strict separation between two independent sources of randomness:

- **Container**: filled by `internal/drbg` (CSPRNG-seeded noise from the operator-selected DRBG fill primitive, AES-256-CTR by default where hardware AES is present and ChaCha20 otherwise) — an external random process.
- **Config**: generated by `ChainHash(seed, nonce)` — an internal, PRF-based derivation.
- **Nonces**: drawn from `crypto/rand` — two independent per-message draws (`main_nonce` for per-pixel/per-region derivations, and `interlock_nonce` for per-chunk mask draws), each up to 512 bits and enforced pairwise-distinct.

The DRBG does not know about the PRF, and the PRF does not know about the DRBG. Their only interaction occurs at embedding, after which an observer sees only the composite result.

**Hash output bandwidth.** Each per-pixel ChainHash call produces 128, 256, or 512 bits depending on the primitive, but the encoder consumes only the low 64 bits. Of these, ~62 bits are actively used (3 for noise position, 56 for channel XOR, and ~3 for rotation); the remainder is discarded.

A single `uint64` register fits the per-pixel requirement directly. This narrowing provides architectural defense-in-depth: any structural weakness or non-uniformity residing in the high bits of an underlying primitive is discarded on the encryption path (see [REDTEAM.md § Broken-primitive stress](REDTEAM.md#broken-primitive-stress--crc128-and-fnv-1a)). For PRF-grade primitives, truncation preserves PRF security under standard assumptions (see [SCIENCE.md § 1.2.2](SCIENCE.md#122-pixel-barrier-per-pixel-channel-xor-rotation-and-noise-injection)).

## 3. Nonce: A New Universe Per Message

Fresh nonces guarantee that encrypting the same message with the same seeds produces:

- A completely different random container (fresh DRBG draw).
- A fresh configuration map (nonce feeds into every ChainHash invocation).
- Three independent start pixel offsets (`main_nonce` feeds `deriveStartPixel`).
- A fresh per-chunk 48-bit permutation draw (`interlock_nonce` feeds `deriveInterLockSeed`).

Repeated transmissions of identical plaintext produce uncorrelated containers. The classic stream-cipher two-time-pad vulnerability is prevented by the per-chunk permutation, resulting in null plaintext recovery (§9).

Both nonces are drawn internally on every call from `crypto/rand` and enforced pairwise-distinct at the API level, preventing caller-side nonce reuse. Formal closure of the CPA and KPA attack families is PRF-conditional on fresh nonces at the construction level (§9).

## 4. 8-Seed Isolation

The construction requires 8 mandatory seeds, drawn as independent CSPRNG components and enforced pairwise-distinct by byte-level `Components` comparison:

- **noiseSeed** → noise position (which bit in each channel holds noise).
- **lockSeed** → 48-bit Interlocked Barrier per-chunk permutation channel.
- **dataSeed1, dataSeed2, dataSeed3** → per-region rotation and XOR configurations.
- **startSeed1, startSeed2, startSeed3** → per-region pixel offsets.

Each seed drives its own ChainHash instance with independent components. Compromising any subset of seeds reveals zero information about the remaining seeds (see [SCIENCE.md § 2.3](SCIENCE.md#23-8-seed-isolation-theorems-3-3a) and [SECURITY.md § 1](SECURITY.md#1-itb-composition-modes)).

The `lockSeed` derives the barrier's permutation independently from the `noiseSeed`, ensuring that an oracle leak on noise positions cannot compromise the permutation channel. Similarly, the 3-region seed split localizes any single-region compromise to that region alone.

## 5. Triple Ouroboros: Three Interleaved Regions

Plaintext never reaches the regions as contiguous bytes. Every message first passes through the Rank Barrier (§12) — a per-chunk PRF-keyed 48-bit permutation — which partitions the input into three region payloads. Each region receives a stream of PRF-permuted 16-bit lane fragments rather than plaintext.

**How plaintext becomes three region payloads:**

1. A 4-byte big-endian length prefix is prepended to the plaintext, allowing exact restoration of the original extent.
2. The byte stream is processed in 48-bit (6-byte) chunks.
3. For each chunk, lane distribution is evaluated through a **two-stage cascade fill** (`lockSeed` + `interlock_nonce`) followed by combinadic unranking into balanced mask triple `(m0, m1, m2)` (see §12 for full derivation).
4. `chunk48lock(x, m0, m1, m2)` compresses the 48-bit chunk into three 16-bit lane values `(l0, l1, l2)` using three BMI2 `PEXTQ` instructions on x86 (or portable fallback) in ~3 cycles per chunk in constant time.
5. Region 0 receives `l0` (2 bytes), Region 1 receives `l1`, and Region 2 receives `l2`, advancing in lockstep.
6. Each region's lane buffer begins with its respective fragment of the interlock nonce. The accumulated payload enters COBS encoding; these fragments sit inside the Pixel Barrier's encryption coverage and are authenticated under AEAD modes (MAC-Inside-Encrypt composition). Nonce splitting is derived deterministically from the configured nonce width, requiring no wire length metadata.

```
Plaintext + 4-byte BE length prefix
        │
        ▼
  ┌─────────────────────────────────────────────────┐
  │ 48-bit chunk 0 │ 48-bit chunk 1 │ 48-bit ... │
  └─────────────────────────────────────────────────┘
        │                │
        ▼                ▼
   PRF-keyed         PRF-keyed
   mask triple 0     mask triple 1     ... (independently keyed per chunk)
   (m0, m1, m2)      (m0, m1, m2)
        │                │
        ▼                ▼
   chunk48lock →     chunk48lock →
   (l0, l1, l2)      (l0, l1, l2)
        │                │
        ▼                ▼
   Region 0 payload:  il_frag0 ‖ l0_chunk0 ‖ l0_chunk1 ‖ ...  (16 bits per chunk)
   Region 1 payload:  il_frag1 ‖ l1_chunk0 ‖ l1_chunk1 ‖ ...
   Region 2 payload:  il_frag2 ‖ l2_chunk0 ‖ l2_chunk1 ‖ ...
```

Without `lockSeed` and `interlock_nonce`, the mapping from plaintext bits to lane positions is an unobservable per-chunk secret produced by the two-stage cascade fill. Known-plaintext cribs provide no fixed bit-to-lane anchor.

**Three parallel DRBG regions.** A single container is allocated and filled by three parallel goroutines via `internal/drbg`:

```
Container (one allocation, three parallel fills):

┌──────────────┬──────────────┬──────────────┐
│  Region 0    │  Region 1    │  Region 2    │
│     DRBG     │     DRBG     │     DRBG     │
│  goroutine 1 │  goroutine 2 │  goroutine 3 │
└──────────────┴──────────────┴──────────────┘
  pixels 0..P/3  pixels P/3..2P/3  pixels 2P/3..P
```

**Three parallel encrypt pipelines.** Each region payload (16-bit fragments) is COBS-encoded, null-terminated, padded with DRBG fill, and encrypted using separate seeds:

```
Region 0 payload (l0 stream) → COBS → [cobs|0x00|fill] → dataSeed1 + startSeed1 + noiseSeed → Region 0
Region 1 payload (l1 stream) → COBS → [cobs|0x00|fill] → dataSeed2 + startSeed2 + noiseSeed → Region 1
Region 2 payload (l2 stream) → COBS → [cobs|0x00|fill] → dataSeed3 + startSeed3 + noiseSeed → Region 2
                                                         ─────────────────────────────────
                                                         3 goroutines, each with numCPU/3 workers
```

Inside each region, the Pixel Barrier applies per-pixel ChainHash derivation, rotation, XOR masking, and noise-bit preservation. The Rank Barrier and Pixel Barrier operate in series as an indivisible composition.

**Per-pixel bit-level processing.** For a lane byte `b` (from Region 0's `l0` stream after COBS framing):

```
b = 01001000 (8 bits of lane data, not plaintext)

Channel 0:  0100100  ← 7 bits extracted from the lane bit stream
            ⊕ XOR mask from dataSeed1 (7 bits per channel)
            = encrypted 7 bits
            rotate(encrypted, rotation1)  ← rotation 0-6 from dataSeed1
            insert into pixel, preserving noise bit at noisePos (from noiseSeed)

Channel 1:  0??????  ← next 7 bits (from b + next lane byte)
            ... same XOR + rotate + insert ...
```

Each lane byte is split across 2 channels (`gcd(7, 8) = 1`). Each channel contains 7 encrypted data bits and 1 noise bit, presenting 8 uniform pseudo-random bits.

**What the attacker sees:**

```
Output: [prefix(32)][main_nonce][W][H][container] (uniform random bytes)

┌──────────────────────────────────────────────────────┐
│ dddddddddddddddddddddddddddddddddddddddddddddddddd  │
│ dddddddddddddddddddddddddddddddddddddddddddddddddd  │
│ dddddddddddddddddddddddddddddddddddddddddddddddddd  │
└──────────────────────────────────────────────────────┘
  ← one continuous block of uniform random bytes →

  No visible boundary between regions.
  No visible startPixel markers (all three hidden).
  No visible data/fill boundary (all three hidden).
```

**Container geometry and floor modes.** Containers are square grids (`W = H = side`) sized to accommodate the three region payloads alongside the DRBG barrier fill margin (`DefaultBarrierFill = 1`):
`side = s + 1`, where `s = ⌈√totalPixels⌉`.

To resist chosen-ciphertext ambiguity reduction, the minimum pixel count enforces `MinPixels = ⌈keyBits / log₂7⌉` (183 / 365 / 730 pixels for 512 / 1024 / 2048-bit keys), ensuring `7^P > 2^keyBits`. Container sizing operates under two modes:

- **Mode 1 (Per-Region, default):** Each of the three regions independently satisfies `MinPixels`. Small messages clamp to `3 × MinPixels` data pixels, yielding a 35 × 35 container (1,225 pixels) at 1024-bit keys.
- **Mode 2 (Per-Container, compact mode):** The ambiguity floor is evaluated jointly across the container (`totalPixels = max(3 × maxDataThirdPixels, MinPixels)`). Small messages clamp to `MinPixels` total pixels, yielding a 21 × 21 container (441 pixels) at 1024-bit keys, reducing wire overhead for MTU-constrained networks.

Both modes converge to identical dimensions once payload volume exceeds the floor. Decoders parse `W` and `H` directly from the frame header; decryption is mode-independent and handles ciphertexts from either mode without configuration.

**Decryption.** After the 32-byte prefix, the header `[main_nonce][W][H]` is parsed, and the container is split into thirds. Three parallel goroutines invert the Pixel Barrier (noise strip, inverse rotation, XOR unmask) and COBS-decode the lane payloads. The leading interlock-nonce fragments are reassembled. Then `interleaveTriple48LockedBatch` reconstructs the 48-bit chunks using mask triples derived from `lockSeed` and `interlock_nonce`, and the 4-byte length prefix is removed to restore the exact original plaintext.

## 6. Under Normal Use: Attack Resistance Summary

Under standard operation with a PRF-grade hash and CSPRNG nonces:

| Attack | What happens | Barrier status |
|---|---|---|
| **COA** (ciphertext only) | Attacker sees random bytes; hash outputs are unobservable | Intact |
| **KPA** (known plaintext) | Container byte values remain unknown; per-chunk permutation is secret | Intact |
| **CPA** (chosen plaintext) | Fresh nonces produce independent configurations; zero cross-message correlation | Intact |
| **CCA** (chosen ciphertext) | Core ITB and MAC + Silent Drop expose no oracle (see [SECURITY.md § 1 note 1](SECURITY.md#1-itb-composition-modes)) | No oracle exists |

Under passive observation (COA, CPA), the barrier absorbs hash outputs. Under Full KPA, resistance is 4-factor under the PRF assumption:

1. **PRF non-invertibility** — candidate hash outputs cannot be verified against seeds without knowledge of the seed.
2. **Rank Barrier per-chunk mask permutation** — each 48-bit chunk is permuted across lanes via a mask drawn from ≈ 2^70.20 balanced partitions.
3. **startPixel isolation** — three independent, non-transmitted offsets (`sp0`, `sp1`, `sp2`) must be jointly enumerated without feedback.
4. **Pixel Barrier ambiguity** — 7 rotations × 8 noise positions maintain 56 equiprobable candidates per pixel at 1:1 signal/noise.

Under Partial KPA, byte-splitting (`gcd(7, 8) = 1`) acts as a 5th factor: candidate formulation is blocked whenever adjacent bytes are missing.

See [SECURITY.md § 3](SECURITY.md#3-attack-resistance-summary) for the complete attack resistance table.

## 7. Byte-Splitting: Why Byte Analysis Does Not Work

Because `gcd(7, 8) = 1` (7 data bits per channel, 8 bits per byte), plaintext bytes never align with channel boundaries. Every plaintext byte is split across exactly 2 channels with independent XOR masks.

An attacker knowing a specific byte value (such as a JSON delimiter `{` or protocol header) cannot analyze it on a single channel because each channel mixes bits from two adjacent bytes. Without the adjacent byte, candidate bits cannot be formulated.

Under Partial KPA, three defensive layers combine:

1. **Barrier** — hash output is unobservable (absorbed in random container).
2. **Byte-splitting** — per-channel byte formulation is blocked (`gcd(7, 8) = 1`).
3. **PRF** — inversion of candidate values is computationally infeasible.

Under Full KPA (where all adjacent bytes are known), byte-splitting provides no additional obstacle, but the defense remains 4-factor under the PRF assumption (see [Proof 4a](PROOFS.md#proof-4a-multi-factor-full-kpa-resistance) and [SCIENCE.md § 2.10](SCIENCE.md#210-byte-splitting-property)).

## 8. Full KPA (PRF Assumption)

Full KPA (where the attacker knows the entire plaintext) is the standard cryptographic baseline:

| Condition | Result |
|---|---|
| Full KPA + invertible primitive | Rank Barrier permutation and multi-seed coupling foreclose SAT-based seed recovery at instance formulation. Bitwuzla does not recover the true seed even under maximum-peek regimes (see [REDTEAM.md § FNV-1a lo-lane SAT](REDTEAM.md#fnv-1a-lo-lane-sat--architecturally-foreclosed)). |
| Full KPA + PRF (non-invertible) | Inversion is infeasible. Work factor reduces to brute-force: `P × 2^(2·keyBits)` (Core ITB) or `P × 2^keyBits` (MAC + Reveal), plus per-chunk mask space (≈ 2^70.20 per chunk). |

Without the barrier, an attacker could test 56 candidates per pixel, invert the hash to recover candidate seeds, and verify across pixels. Under a PRF, candidate verification is infeasible. Under an invertible primitive, the Rank Barrier removes the fixed position-to-lane mapping needed to verify on a second pixel.

**Full KPA under hypothetical total PRF inversion.** Total inversion of the underlying primitive would collapse the construction (see [Proof 4a](PROOFS.md#proof-4a-multi-factor-full-kpa-resistance)): the Pixel Barrier through direct inversion, and the Rank Barrier through mask observation. The multi-factor property protects against partial primitive weaknesses and any degree of architectural weakness, but cannot withstand total PRF failure. Within partial PRF weakness, occasional or sporadic inversion events are absorbed — the architectural obstacles generate a false-positive distribution that hides true candidates. Systematic partial inversion is not absorbed; the architecture elevates computational cost but does not eliminate the attack. No such systematic weakness is currently known.

**Full KPA under non-invertible PRF.** Resistance is 4-factor: (1) PRF non-invertibility prevents candidate verification, (2) Rank Barrier per-chunk mask permutation multiplies enumeration by ≈ 2^70.20 without coupling adjacent chunks, (3) startPixel isolation requires joint enumeration of non-transmitted offsets (`sp0`, `sp1`, `sp2`), and (4) Pixel Barrier ambiguity maintains 56 candidates per pixel at 1:1 signal/noise. Under Partial KPA, byte-splitting (`gcd(7, 8) = 1`) acts as a 5th factor by blocking candidate formulation whenever adjacent bytes are missing.

## 9. Nonce Reuse: A Usage Precondition, Not an Absorbed Threat

The construction utilizes two independent nonces: `main_nonce` (governing per-pixel and per-region derivations) and `interlock_nonce` (governing per-chunk mask selections). Both are generated internally from `crypto/rand` and enforced distinct. Reaching a caller-forced reuse condition through the shipped API is prevented by internal CSPRNG generation; birthday collisions at 512 bits require ~2^256 messages, and reuse can only be simulated in the lab via test overrides.

At the default 512-bit width, birthday collision on either slot requires ~2^256 messages. Within one message (64 MB cap, about 2^23.4 chunks of 48 bits) a repeated per-chunk mask is expected with probability ~2^-24. Simultaneous collision on both slots requires a CSPRNG hardware failure.

Three collision scenarios exist in lab testing:

- **Scenario A — dual-slot collision:** Both nonces repeat. All derivations repeat (mask triples, rotations, XOR masks, start pixels).
- **Scenario B — main-only collision:** `main_nonce` repeats, `interlock_nonce` is fresh. Pixel configs repeat, but mask permutations re-randomize.
- **Scenario C — interlock-only collision:** `interlock_nonce` repeats, `main_nonce` is fresh. Permutations repeat, but pixel configs re-randomize.

**Empirical verdict: plaintext recovery is null across all scenarios at tested sample sizes** (see [REDTEAM.md § Nonce reuse](REDTEAM.md#nonce-reuse-lab-only)). Even in Scenario A, the container XOR exposes data only up to the Rank Barrier's permutation. The lane assignment remains an unobservable per-chunk secret protected by the two-stage cascade fill (intermediate key derivation under domain tag `0x04`, primer-round ChainHash cascade over `[0x03 ‖ LE64(groupIdx) ‖ 4×0x00]`, and combinadic unranking into hardware PEXT mask triples). Zero bytes are recovered across both random and near-identical plaintext pairs.

**Demasking is not plaintext recovery.** In a stream cipher, `C1 ⊕ C2` directly yields `P1 ⊕ P2`. In ITB, raw ciphertext XOR carries the difference of independent DRBG containers along with per-pixel rotations and XOR masks, and does not reduce to plaintext XOR. A dedicated demasker that strips these layers exposes only the raw PRF hash-output stream up to the barrier permutation, never plaintext bits. On the shipped wire, the per-chunk permutation removes the demasking anchor entirely — the lane assignment remains an unobservable per-chunk secret protected by the two-stage cascade fill.

## 10. CCA: Reveals Only Noise, Not Data

Under CCA (chosen ciphertext with MAC verification feedback), bit-flipping reveals noise bit positions (3 bits per pixel from `noiseSeed`). Because of 8-seed isolation:

- **noiseSeed config** — revealed via CCA.
- **dataSeed configs** (rotation + 56 XOR bits per region) — independent, zero leak.
- **startSeed configs** (offsets) — independent, zero leak.
- **lockSeed** (permutation channel) — independent, zero leak.

With noise positions known, candidate configurations drop from 56 to 7 per pixel (rotation unknown). Without an invertible hash, the attacker cannot verify candidates, and the per-chunk permutation remains unobservable.

**DRBG residue in data positions (Theorem 10).** Stripping noise bits exposes 7 data bits per channel, but these contain a mixture of encrypted payload and encrypted DRBG fill bytes, processed identically by `dataSeed`. Because containers enforce dimensions `(s+1) × (s+1)` where `s = ⌈√totalPixels⌉` and `totalPixels` satisfies the ambiguity floor `MinPixels = ⌈keyBits / log₂(7)⌉`, capacity strictly exceeds payload: `gap ≥ (2s + 1) × 7 bytes > 0` ([Proof 10](PROOFS.md#proof-10-guaranteed-drbg-residue-no-perfect-fill), [SCIENCE.md § 2.9](SCIENCE.md#29-guaranteed-drbg-residue-theorem-10)). At 1024-bit keys (`MinPixels = 365`), Mode 1 (per-region, `3 × 365 = 1095` pixels, `s = 34`, container `35 × 35 = 1225` pixels) yields `gap ≥ 483 bytes`; Mode 2 (per-container, `totalPixels = 365`, `s = 20`, container `21 × 21 = 441` pixels) yields `gap ≥ 287 bytes`. The attacker cannot distinguish payload from fill without `dataSeed`.

CCA leaks 3/62 ≈ 4.8 % of per-pixel configuration, reducing brute-force complexity from `P × 2^(2·keyBits)` to `P × 2^keyBits` (eliminating `noiseSeed`). No plaintext, XOR masks, offsets, or permutations are leaked.

See [SECURITY.md § 2](SECURITY.md#2-cca-oracle-leak-comparison), [SCIENCE.md § 2.8](SCIENCE.md#28-cca-leak-upper-bound-theorem-6), and [Proof 10](PROOFS.md#proof-10-guaranteed-drbg-residue-no-perfect-fill).

## 11. startPixels: Not Transmitted, Not Recoverable

Each region's `startPixel` is derived in registers from its `startSeed` and `main_nonce` via ChainHash. Offsets are neither transmitted nor stored.

The only theoretical recovery path is a local cache side-channel on the CPU. Even with CCA and a side-channel leak of one `startPixel`, the attacker faces 7 rotation candidates per pixel and the unobservable per-chunk permutation, reducing to `2^keyBits` brute-force on that region alone. The remaining two regions remain isolated (see [SCIENCE.md § 2.3](SCIENCE.md#23-8-seed-isolation-theorems-3-3a)).

## 12. The Interlocked Barrier

The Interlocked Barrier is an always-on layer composing two inseparable mechanisms:

- **Rank Barrier** — a per-chunk 48-bit keyed permutation over the interleaved payload, drawn from a space of ≈ 2^70.20 balanced partitions keyed by `lockSeed` and `interlock_nonce`.
- **Pixel Barrier** — a per-pixel encoding stage masking each channel byte via channel XOR, 7-position rotation, and noise-bit insertion, keyed by `dataSeed` and `noiseSeed`.

Rank Barrier denies a stable bit-to-lane mapping; Pixel Barrier denies a per-byte observation channel. Neither runs in isolation.

**Rank Barrier — two-stage cascade fill and 48-bit chunk permutation.** Plaintext bits are never mapped to lanes by `lockSeed` directly. Instead, lane distribution is evaluated through a two-stage cascade:

1. **Intermediate key derivation:** An intermediate key `K = deriveInterLockSeed(interlock_nonce)` is derived under domain tag `0x04` via a full ChainHash cascade over `[0x04 ‖ interlock_nonce]` keyed by `lockSeed`.
2. **Primer round and session-component feed-forward:** The builder constructs the prepended component slice `lockComps = [K[0], ..., K[w-1], c[0], ..., c[n-1]]` (where `w = width / 64` words and `c` are `lockSeed.Components`). Round 1 is the dedicated **primer round** seeded with intermediate key `K`; rounds 2 .. 1 + keyBits/width feed the state forward through the session components.
   Distinction from Pixel Barrier: The Pixel Barrier operates directly over session components at depth `r = keyBits / width` (4 / 8 / 16 rounds at width 128 for 512 / 1024 / 2048-bit keys; 2 / 4 / 8 at width 256; 1 / 2 / 4 at width 512), without an intermediate key. The Interlocked Barrier operates at depth `r = 1 + keyBits / width` (5 / 9 / 17 rounds at width 128; 3 / 5 / 9 at width 256; 2 / 3 / 5 at width 512), where the additional primer round binds every chunk's rank to `interlock_nonce` before session components are mixed. The Rank Barrier cascade fill is **exactly 1 round deeper** than the Pixel Barrier cascade.
3. **Per-chunk rank evaluation:** Each group evaluates input block `[0x03 ‖ LE64(groupIdx) ‖ 4×0x00]` (13 bytes) through the cascade over `lockComps`, yielding a 128-bit rank per chunk.
4. **Combinadic unranking:** The rank reduces to `(idx0, idx1)` via `(q, idx1) = divmod128(rank, B)` and `idx0 = q mod A`, mapped to disjoint 16-of-48 masks `(m0, m1, m2)` via binomial combinatorial unranking.
5. **Constant-time hardware execution:** Three BMI2 `PEXTQ` instructions (`chunk48LockBatch`) compress the 48-bit chunk into three 16-bit lane values in ~3 cycles per chunk in constant time. Reassembly uses three BMI2 `PDEPQ` instructions followed by pairwise `ORQ`.

**Mask-space cardinality (Theorem 11).** The number of balanced partitions per chunk is ([Proof 11](PROOFS.md#proof-11-48-bit-rank-barrier-mask-space-interlocked-barrier), [SCIENCE.md § 2.15](SCIENCE.md#215-48-bit-rank-barrier-mask-space-theorem-11)):

- `A = C(48, 16) = 2,254,848,913,647` (log₂ ≈ 41.04) — choices for `m0`.
- `B = C(32, 16) = 601,080,390` (log₂ ≈ 29.16) — choices for `m1` from remaining bits (`m2` complement).
- `A · B = 1,355,345,464,406,015,082,330` (log₂ ≈ 70.20).

Under the PRF assumption, recovered masks carry zero information about neighboring chunks: a known crib chunk multiplies candidate enumeration by ≈ 2^70.20 without coupling constraints across chunks, turning cryptanalysis into an instance-formulation closure ([Proof 11](PROOFS.md#proof-11-48-bit-rank-barrier-mask-space-interlocked-barrier)).

**Algebraic under-determination at 48 known bits.** Even granting an attacker all 48 known plaintext bits of a chunk under Full KPA, the observation does not determine the chunk's mask: the number of preimages per mask triple is `⌊2^128 / (A · B)⌋ ≈ 2^57.80`, and every candidate mask remains consistent with the observation. Combined with the Pixel Barrier's 1:1 signal/noise ambiguity, the attacker has no ranking signal among the ≈ 2^70.20 masks.

**Two-step reduction and gcd(A, B) anti-collapse (Theorem 12).** The mask triple is derived from a 128-bit PRF rank via ([Proof 12](PROOFS.md#proof-12-gcda-b-anti-collapse-trap), [SCIENCE.md § 2.16](SCIENCE.md#216-gcda-b-anti-collapse-trap-theorem-12)):
`idx1 = rank mod B`, `idx0 = ⌊rank / B⌋ mod A`.

This reaches the full `[0, A) × [0, B)` space near-uniformly. The naive alternative `(rank mod A, rank mod B)` is flawed because `gcd(A, B) = gcd(C(48, 16), C(32, 16)) = 66,861 = 3² · 17 · 19 · 23`, which would restrict reachable pairs to `1 / 66,861 ≈ 1.5 × 10⁻⁵` of the space (eroding `log₂ 66,861 ≈ 16.03` bits of entropy). The two-step divmod reduction preserves the full ≈ 2^70.20 space.

**Bias distribution.** The two-step reduction carries a fixed relative deviation of ≈ 2^-57.8 per chunk on the lowest `2^128 mod (A · B)` pairs. Accumulated linearly over a maximum message of 2^23.42 chunks, deviation is bounded by ≈ 2^-34.4. Detecting this would require ~2^115.6 chunk samples (~2^92 maximum-size messages), far beyond any attainable data budget.

**Pixel Barrier — per-pixel absorption.** Each pixel packs 56 data bits into 8 channel bytes labelled with the RGBWYOPA mnemonic (Red, Green, Blue, White, Yellow, Orange, Purple, Alpha) as byte-unit positions, unrelated to image processing. Each channel undergoes 7-bit XOR masking, 7-position rotation, and insertion of an original DRBG noise bit at `noisePos`.

**The absorption guarantee:** Under passive observation across unknown uniform plaintext, for any observed byte `v` and hash output `h`, `P(v | h) = 1/256` ([Proof 1](PROOFS.md#proof-1-information-theoretic-barrier)); conditional on fixed lane data `d`, each of the two candidate byte values occurs with probability `P(v | h, d) = 1/2`. Because the noise bit originates from the DRBG, observations do not uniquely determine hash outputs.

**Why KPA candidates do not break the barrier.** An attacker can calculate 56 candidate hash outputs per pixel, but all 56 are equally consistent with observation. Without ChainHash inversion, the candidate space cannot be narrowed. Under an invertible primitive, inverting ChainHash bypasses the Pixel Barrier's per-pixel ambiguity, but the Rank Barrier's per-chunk permutation remains — the mapping from plaintext bits to lane positions is a hidden secret that primitive inversion cannot recover. Direct guessing of the 62-bit-per-pixel configuration map requires `2^(62·P)` attempts (≈ 2^75950 for 1024-bit keys), far exceeding the key space.

**Cost and mandatory enforcement.** On x86 BMI2, the apply kernel executes via three PEXT (forward) and three PDEP (inverse) operations per chunk. Unranking runs on AVX-512F or AVX2 SIMD kernels, with portable Pure Go fallbacks. Every exported entrypoint of the `itb.Encrypt3x*` and `Decrypt*` families, as well as all shipped `Triple` profiles, routes through the Interlocked Barrier unconditionally; no runtime bypass knob exists.

## 13. Quantum Resistance

The barrier relies on information absence rather than computational hardness alone: an observation contains insufficient information to reconstruct hash outputs. This property is computation-model-independent:

- **Grover** — requires a verification oracle. Core ITB and MAC + Silent Drop offer no oracle; `noiseSeed` and `dataSeed` must be searched jointly, with start pixels enumerated and per-chunk masks unobservable.
- **Simon** — requires periodic structure. Aperiodic nonces (up to 512 bits) ensure fresh configurations per message.
- **BHT** — requires observable collisions. The random container and per-pixel encoding ambiguity absorb collisions before observation.
- **Q2 superposition queries** — precluded; the MAC oracle is strictly classical and network-bounded.

At 1024-bit key sizes, search complexities vastly exceed foreseeable quantum limits.

## 14. Per-Candidate Cost: Why Brute-Force Is Slow

Unlike AES or ChaCha20 where testing a key takes nanoseconds on a single block, testing an ITB key requires decrypting the entire container:

| Data size | P (pixels) | Time per attempt | vs AES |
|---|---|---|---|
| Min container (Mode 1, payload ≤ ~7.9 KB, 1024-bit key) | 1,225 | ~196 µs | ~196,000× slower |
| Min container (Mode 2, payload ≤ ~2.6 KB, 1024-bit key) | 441 | ~70 µs | ~70,000× slower |
| 4 MB | 603,729 | ~96 ms | ~96 million× slower |
| 16 MB | 2,411,809 | ~385 ms | ~385 million× slower |
| 64 MB | 9,634,816 | ~1.5 s | ~1.5 billion× slower |

Estimates assume a 1024-bit key (128-bit primitive, ~10 ns per hash round on modern hardware, 8 sequential ChainHash rounds per pixel) plus per-chunk combinadic unranking. ChainHash rounds are strictly sequential and cannot be parallelized.

## 15. Barrier and PRF: Symbiosis

The barrier and the PRF primitive protect each other:

- **PRF protects the barrier:** Non-invertibility prevents an attacker from resolving the 56-to-1 per-pixel ambiguity and the per-chunk ≈ 2^70.20 mask space.
- **Barrier protects the PRF:** Two pixels with identical hash outputs receive different container bytes from the DRBG, so their observed bytes differ. The collision is absorbed. The inseparable Interlocked Barrier absorbs a broad spectrum of primitive weaknesses beneath its composite layers: output collisions, statistical non-uniformities, structural biases, and trapdoor effects (such as the BEA-1 partition trapdoors documented in [HARNESS.md](HARNESS.md)) are masked by random container noise insertion, independent rotation, and per-chunk lane scrambling. Even below-spec stress primitives exhibit zero observable leakage when enveloped by the full barrier.
- **ChainHash architecture resists MITM:** Sequential component mixing ensures that partial key compromise reveals nothing about adjacent components.

Together, non-invertibility blocks inversion, and the barrier absorbs primitive defects. Under passive observation, the composite cipher behaves as an ideal random permutation. Under active cryptanalysis and Full KPA, resistance remains strictly conditional on PRF non-invertibility, as total primitive inversion collapses the composite construction via algorithmic recovery.

## 16. Oracle-Free Deniability

Decryption with an incorrect seed constellation produces uniform random bytes with no distinguishing signal:

- **No magic bytes or file headers:** Wire containers consist solely of `[prefix(32)][main_nonce][W][H][container]`, the prefix being CSPRNG output.
- **No plaintext length header:** Length metadata is encrypted inside the container across chunk boundaries.
- **Encrypted null terminator:** COBS termination is hidden within the ciphertext.
- **No padding:** Rotation and XOR masking provide confidentiality without padding markers.
- **Uniform failure:** Wrong seeds produce pseudorandom bytes indistinguishable from random data.
- **Silent drop:** MAC failure drops silently without leaking verification feedback in Core ITB and MAC + Silent Drop modes (under MAC + Reveal, CCA interaction exposes only the 3-bit noise position oracle, leaving plaintext and other seeds unobservable).

Deployments requiring full oracle-free deniability operate under Core ITB or MAC + Silent Drop, ensuring incorrect keys or altered ciphertexts produce zero verification feedback.

## 17. Custom Primitives

ITB allows custom hash primitives through two native extension points:

1. **Direct closures at the Low-Level surface:** Pass `itb.HashFunc{N}` and `itb.BatchHashFunc{N}` closures directly to `*Cfg` functions.
2. **Registration via `hashes.Register`:** Add a primitive to the runtime registry by name, enabling use within `triple.Profile` and `triple.Init`.

**Key constraints:**
- Custom registration is a Go-native feature only; FFI bindings consume the frozen C ABI and do not expose dynamic primitive registration.
- Registration is immutable: names cannot be overwritten or redefined once registered.

For complete examples and implementation guidelines, see [README.md § Custom user-supplied hashes](README.md#custom-user-supplied-hashes) and [hashes/README.md](hashes/README.md).

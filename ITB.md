## 1. The Core Idea: Absorption

The shipped construction composes two inseparable mechanisms — a per-chunk keyed permutation (Rank Barrier, operating over 48-bit chunks by default or 168-bit chunks under `Interlock = "168"` on 512-bit primitives) and a per-pixel absorption stage (Pixel Barrier), described in detail in §12. This section outlines the absorption intuition provided by the Pixel Barrier.

The hash output is computed and determines the pixel configuration, but it is absorbed into a random container. The observer sees only: random byte ± modification. Because the original random byte is unknown, the modification is unknown, making the hash output unobservable.

This is not encryption layered on top, but absorption — the random container fully absorbs the hash output. Like dropping a drop of paint into an ocean of random waves, the paint is present, but an observer sees only waves.

Under passive observation, this property is computation-model-independent: no amount of computational power can extract information that is not present in the observation.

**Formal basis:** `∀v, ∀h : ∃(c, d) : embed(c, h, d) = v` — for every observed byte value and every possible hash output, there exists a container byte and data configuration that produces that exact observation (see [Proof 1](PROOFS.md#proof-1-information-theoretic-barrier), [lean/README.md](lean/README.md), [SCIENCE.md § 2.1 Theorem 1](SCIENCE.md#21-information-theoretic-barrier-theorem-1), and [SECURITY.md § 4](SECURITY.md#4-information-theoretic-barrier-metrics)).

## 2. Three Independent Sources of Randomness

The barrier relies on strict separation between three independent sources of randomness:

- **Container**: filled by `internal/drbg` (CSPRNG-seeded noise from the operator-selected DRBG fill primitive, AES-256-CTR by default where hardware AES is present and ChaCha20 otherwise) — an external random process.
- **Config**: generated by `ChainHash(seed, nonce)` — an internal, PRF-based derivation.
- **Nonces**: drawn from `crypto/rand` — two independent per-message draws (`main_nonce` for per-pixel/per-region and **Layer I** sub-region trajectory derivations under `0x02`/`0x05`, and `interlock_nonce` for per-chunk mask draws and **Layer II** cross-lane slot desynchronization under `0x03`/`0x04`/`0x06`), each up to 512 bits and enforced pairwise-distinct.

The DRBG does not know about the PRF, and the PRF does not know about the DRBG. Their only interaction occurs at embedding, after which an observer sees only the composite result.

**Hash output bandwidth.** Each per-pixel ChainHash call produces 128, 256, or 512 bits depending on the primitive, but the Pixel Barrier encoder consumes only the low 64 bits of the `dataSeed_i` call (and of the `startPixel_i` `0x02` call) and a 3-bit XOR fold of the first two 64-bit words of the `noiseSeed` call (`h[0] + rotl64(h[1], 1)`). Of the data word, ~59 bits are actively used (56 for channel XOR and ~3 for rotation); the remainder is discarded. In contrast, the Rank Barrier (`0x03`/`0x04`) and **Layer I** / **Layer II** of the **Desynchronized Interlocked Barrier** (`0x05`/`0x06` via a 128-bit Feistel-like bijection) consume both 64-bit words of each 128-bit output pair without truncation.

A single `uint64` register fits the per-pixel requirement directly. This narrowing provides architectural defense-in-depth: any structural weakness or non-uniformity residing in the high bits of an underlying primitive is discarded on the encryption path (see [REDTEAM.md § Broken-primitive stress](REDTEAM.md#broken-primitive-stress--crc128-and-fnv-1a)). For PRF-grade primitives, truncation preserves PRF security under standard assumptions (see [SCIENCE.md § 1.2.3](SCIENCE.md#123-pixel-barrier-per-pixel-channel-xor-rotation-and-noise-injection)).

## 3. Nonce: A New Universe Per Message

Fresh nonces guarantee that encrypting the same message with the same seeds produces:

- A completely different random container (fresh DRBG draw).
- A fresh configuration map (nonce feeds into every ChainHash invocation).
- Three independent start pixel offsets (`0x02`) and **Layer I** dynamic sub-region trajectory schedules `Π_0, Π_1, Π_2` (`0x05`) derived from `main_nonce` and `startSeed1..3`.
- A fresh per-chunk 48-bit (or 168-bit under `Interlock = "168"`) permutation draw (`0x03`) and **Layer II** cross-lane chunk-slot desynchronization `Σ_0, Σ_1, Σ_2` (`0x06`) derived from `interlock_nonce` and `lockSeed` (under domain tag `0x04`).

Repeated transmissions of identical plaintext produce uncorrelated containers. The classic stream-cipher two-time-pad vulnerability is prevented by the per-chunk permutation, resulting in null plaintext recovery (§9).

Both nonces are drawn internally on every call from `crypto/rand` and enforced pairwise-distinct at the API level, preventing caller-side nonce reuse. With fresh nonces, formal seed-recovery bounds under the CPA and KPA attack families remain computational and PRF-conditional, while instance-formulation and solver resistance arise jointly from the PRF cascade and the **Desynchronized Interlocked Barrier** (§8, §9, §12).

## 4. 8-Seed Isolation

The construction requires 8 mandatory seeds, drawn as independent CSPRNG components and enforced pairwise-distinct by byte-level `Components` comparison:

- **noiseSeed** → noise position (which bit in each channel holds noise).
- **lockSeed** → Interlocked Barrier per-chunk permutation channel (`48`-bit default `"48"`, or `168`-bit `"168"` on 512-bit primitives; domain tags `0x03` / `0x04`) and **Layer II** cross-lane chunk-slot desynchronization (domain tag `0x06`).
- **dataSeed1, dataSeed2, dataSeed3** → per-region rotation and XOR configurations.
- **startSeed1, startSeed2, startSeed3** → per-region pixel offsets (`0x02`) and **Layer I** dynamic sub-region trajectory schedules (domain tag `0x05`).

Each seed drives its own ChainHash instance with independent components. Compromising any subset of seeds reveals zero information about the remaining seeds (see [SCIENCE.md § 2.3](SCIENCE.md#23-8-seed-isolation-theorems-3-3a) and [SECURITY.md § 1](SECURITY.md#1-itb-composition-modes)).

The `lockSeed` derives the barrier's per-chunk mask permutation and **Layer II** cross-lane slot desynchronization independently from the `noiseSeed`, ensuring that an oracle leak on noise positions cannot compromise the permutation channel. Similarly, the 3-region seed split localizes any single-region compromise to that region alone.

## 5. Triple Ouroboros: Three Interleaved Regions

Plaintext never reaches the regions as contiguous bytes. Every message first passes through the Rank Barrier (§12) — a per-chunk PRF-keyed permutation — which partitions the input into three region payloads. In the default 48-bit mode (`Interlock = "48"` or `""`), each 48-bit (`6`-byte) chunk is partitioned into three 16-bit (`2`-byte) lane fragments across `|Ω_chunk| ≈ 2^70.20` balanced partitions. When paired with a 512-bit inner primitive (`areion512` or `blake2b512`), callers can select the strategic 168-bit mode (`Interlock = "168"`), which partitions each 168-bit (`21`-byte) chunk into three 56-bit (`7`-byte) lane fragments — exactly one 56-bit pixel data payload per region — across `|Ω_chunk,168| ≈ 2^258.60` balanced partitions.

**How plaintext becomes three region payloads:**

1. A 4-byte big-endian length prefix is prepended to the plaintext, allowing exact restoration of the original extent.
2. The byte stream is processed in 48-bit (`6`-byte) chunks by default, or in 168-bit (`21`-byte) chunks under `Interlock = "168"`.
3. For each chunk, lane distribution is evaluated through a **two-stage cascade fill** (`lockSeed` + `interlock_nonce`) followed by combinadic unranking into a balanced mask triple `(m0, m1, m2)` — three disjoint 16-of-48 masks in 48-bit mode, or three disjoint 56-of-168 masks (`[3]uint64` each) in 168-bit mode (see §12 for full derivation).
4. In 48-bit mode, each 48-bit chunk is compressed into three 16-bit lane values `(l0, l1, l2)` using three BMI2 `PEXTQ` bit-extract instructions on x86-64 (ARM64 SVE2 `BEXT`, or a constant-time branchless software fallback) in ~3 cycles per chunk in constant time (AMD Zen 1 / Zen 2: [microcoded](HWTHREATS.md#52-microarchitecture-floors--tier-dispatch)). In 168-bit mode, each 168-bit (3-word) chunk is compressed into three 56-bit lane values `(l0, l1, l2)` via nine BMI2 `PEXTQ` instructions (`3 words × 3 lanes`) stitched with population-count shifts on x86-64, ARM64 SVE2 `BEXT`, or a constant-time 56-step branchless software fallback (see [KERNELS.md](KERNELS.md) and [HWTHREATS.md](HWTHREATS.md)).
5. Region 0 receives `l0` (`2` bytes in 48-bit mode; `7` bytes in 168-bit mode), Region 1 receives `l1`, and Region 2 receives `l2`. Instead of keeping slot `j` aligned across all three lanes (`l0[j], l1[j], l2[j]` from the same chunk `j`), **Layer II** (keyed by `lockSeed` and `interlock_nonce` under domain tag `0x06`; see [lean/README.md](lean/README.md)) cyclically shifts the `M` chunk slots into `(p0, p1, p2)` by guaranteed distinct offsets (`β_0 ≠ β_1 ⟹ Σ_0(j) ≠ Σ_1(j)`). At every pre-COBS slot position `j`, the three lane fragments `(p0[j], p1[j], p2[j])` originate from at least two distinct plaintext chunks (§12).
6. Each region's lane buffer begins with its respective fragment of the interlock nonce. The accumulated payload enters COBS encoding; these fragments sit inside the Pixel Barrier's encryption coverage and are authenticated under AEAD modes (MAC-Inside-Encrypt composition). Nonce splitting is derived deterministically from the configured nonce width, requiring no wire length metadata.

```
Plaintext + 4-byte BE length prefix
        │
        ▼
  ┌─────────────────────────────────────────────────────────────────────┐
  │ 48-bit (6 B) or 168-bit (21 B) chunk 0 │ chunk 1 │ chunk 2 ...      │
  └─────────────────────────────────────────────────────────────────────┘
        │                                    │
        ▼                                    ▼
   PRF-keyed                            PRF-keyed
   mask triple 0                        mask triple 1     ... (independently keyed per chunk)
   (m0, m1, m2)                         (m0, m1, m2)
        │                                    │
        ▼                                    ▼
   Bit-extract into 3 lanes →           Bit-extract into 3 lanes →
   (l0[0], l1[0], l2[0])                (l0[1], l1[1], l2[1])
        │                                    │
        └─────────────────┬──────────────────┘
                          ▼
  ┌─────────────────────────────────────────────────────────────────────┐
  │ Layer II: Cross-Lane Slot Desynchronization (tag 0x06, lockSeed)    │
  │                                                                     │
  │ Permutes the M chunk slots per lane with distinct cyclic shifts     │
  │ (where Σ_ℓ(j) shifts slot j by β_ℓ, β_0 ≠ β_1):                     │
  │   p0[Σ_0(j)] = l0[j]                                                │

                          │

   Region 0 payload:  il_frag0 ‖ p0[0] ‖ p0[1] ‖ ...  (slot-permuted 16-bit slots in "48"; 56-bit / 7 B slots in "168")
   Region 1 payload:  il_frag1 ‖ p1[0] ‖ p1[1] ‖ ...
   Region 2 payload:  il_frag2 ‖ p2[0] ‖ p2[1] ‖ ...
```

Without `lockSeed` and `interlock_nonce`, the mapping from plaintext bits to lane positions and pre-COBS chunk slots `(p0, p1, p2)` is an unobservable per-chunk and per-lane secret produced by the two-stage cascade fill. Known-plaintext cribs provide no fixed bit-to-lane or slot-to-slot anchor.

**Three parallel DRBG regions.** A single container is allocated and filled by three parallel goroutines via `internal/drbg`:

```
Container (one allocation, three parallel fills):

┌──────────────┬──────────────┬──────────────┐
│  Region 0    │  Region 1    │  Region 2    │
│     DRBG     │     DRBG     │     DRBG     │
│  goroutine 1 │  goroutine 2 │  goroutine 3 │
└──────────────┴──────────────┴──────────────┘
  pixels 0..P/3  pixels P/3..2P/3  pixels 2P/3..P
```

**Three parallel encrypt pipelines and Layer I sub-region trajectories.** Each region payload (16-bit lane fragments in 48-bit mode, or 56-bit lane fragments in 168-bit mode) is COBS-encoded, null-terminated, padded with DRBG fill, and encrypted using separate seeds:

```
Region 0 payload (p0 stream) → COBS → [cobs|0x00|fill] → Layer I (startSeed1, 0x05) + Pixel Barrier (dataSeed1 + noiseSeed) → Region 0
Region 1 payload (p1 stream) → COBS → [cobs|0x00|fill] → Layer I (startSeed2, 0x05) + Pixel Barrier (dataSeed2 + noiseSeed) → Region 1
Region 2 payload (p2 stream) → COBS → [cobs|0x00|fill] → Layer I (startSeed3, 0x05) + Pixel Barrier (dataSeed3 + noiseSeed) → Region 2
                                                         ──────────────────────────────────────────────────────────────────
                                                         3 goroutines, each with numCPU/3 workers
```

Instead of writing sequential payload bytes across a region in a single contiguous cyclic loop, **Layer I** (domain tag `0x05` on `startSeed1..3`; see [lean/README.md](lean/README.md)) breaks each region `r ∈ {0, 1, 2}` of `P_r` pixels into a secret dynamic number of sub-regions (`K_r ∈ [6, 10]` on the **Mode 2** and **Mode 3** floors, or `K_r ∈ [8, 16]` on the **Mode 1** floor) with telescopic boundary jitter (`∑ M_{r,k} = P_r`), shuffles the order in which those sub-regions are visited via a Fisher-Yates permutation `τ_r ∈ S_{K_r}`, and walks each sub-region cyclically from its own independent local starting pixel `s_{r,k} ∈ [0, M_{r,k})`:

```
Region r physical pixel slice (P_r pixels, partitioned with telescopic boundary jitter):

  ┌────────────────────┬──────────────────┬───────────┬─────────────────────┐
  │   Sub-region 0     │   Sub-region 1   │    ...    │  Sub-region K_r - 1 │
  │    (M_{r,0} px)    │   (M_{r,1} px)   │           │  (M_{r,K_r-1} px)   │
  │  local start s_{r,0}│ local start s_{r,1}│         │ local start s_{r,K_r-1}│
  └────────────────────┴──────────────────┴───────────┴─────────────────────┘
            ▲                    ▲                               ▲
            │ 2nd visited        │ 1st visited                   │ K_r-th visited
            └────────────────────┴───────────────┬───────────────┘
                                                 │
         Layer I (tag 0x05 on startSeed_r + main_nonce):
         1. Dynamic sub-region count K_r ∈ [6, 10] (Mode 2 / Mode 3) or [8, 16] (Mode 1)
         2. Jittered boundaries M_{r,k} summing to P_r (no gaps, no overlaps)
         3. Fisher-Yates visit order τ_r = (τ_r(0), τ_r(1), ..., τ_r(K_r - 1))
         4. Cyclic walk inside each visited sub-region k starting at s_{r,k}
```

Inside each visited sub-region, the Pixel Barrier applies per-pixel ChainHash derivation, rotation, XOR masking, and noise-bit preservation at each mapped physical pixel. The Rank Barrier (**Layer II** slot desynchronization + `PEXTQ` bit partitioning) and Pixel Barrier (**Layer I** sub-region trajectory + per-pixel absorption) operate in series as an indivisible composition.

**Per-pixel bit-level processing.** For a lane byte `b` (from Region 0's `p0 / l0` stream after COBS framing):

```
b = 01001000 (8 bits of lane data, not plaintext)

Channel 0:  0100100  ← 7 bits extracted from the lane bit stream
            ⊕ XOR mask from dataSeed1 (7 bits per channel)
            = encrypted 7 bits
            rotate(encrypted, rotation1)  ← rotation 0-6 from dataSeed1
            insert into pixel, preserving noise bit at noisePos (from noiseSeed)

Channel 1:  0??????  ← next 7 bits (from b + next lane byte)
            ... same XOR + rotate + insert ...
```

Each lane byte is split across 2 channels (`gcd(7, 8) = 1`). Each channel contains 7 encrypted data bits and 1 noise bit, presenting 8 uniform pseudo-random bits.

**What the attacker sees:**

```
Output: [prefix(32)][main_nonce][W][H][container] (uniform random bytes)

┌──────────────────────────────────────────────────────┐
│ dddddddddddddddddddddddddddddddddddddddddddddddddd  │
│ dddddddddddddddddddddddddddddddddddddddddddddddddd  │
│ dddddddddddddddddddddddddddddddddddddddddddddddddd  │
└──────────────────────────────────────────────────────┘
  ← one continuous block of uniform random bytes →

  No visible boundary between regions.
  No visible startPixel or Layer I sub-region boundary markers (all hidden).
  No visible data/fill boundary (all three hidden).
```

**Container geometry and floor modes.** Containers are square grids (`W = H = side`) sized to accommodate the three region payloads alongside the DRBG barrier fill margin (`DefaultBarrierFill = 1`):
`side = s + 1`, where `s = ⌈√totalPixels⌉`.

To resist chosen-ciphertext ambiguity reduction, the minimum pixel count enforces `MinPixels = ⌈keyBits / log₂7⌉` (183 / 365 / 730 pixels for 512 / 1024 / 2048-bit keys), ensuring `7^P > 2^keyBits`. Container sizing operates under three modes:

- **Mode 1 (Per-Region, default):** Each of the three regions independently satisfies `MinPixels`. Small messages clamp to `3 × MinPixels` data pixels, yielding a 35 × 35 container (1225 pixels) at 1024-bit keys.
- **Mode 2 (Per-Container, compact mode):** The ambiguity floor is evaluated jointly across the container (`totalPixels = max(3 × maxDataThirdPixels, MinPixels)`). Small messages clamp to `MinPixels` total pixels, yielding a 21 × 21 container (441 pixels) at 1024-bit keys, reducing wire overhead for MTU-constrained networks.
- **Mode 3 (Gauss-Posit, inscribed-circle mode):** Combines an inscribed-circle container floor with secret-regime posit and quire trajectory arithmetic. Instead of sizing the floor to the full three-region bounding square (**Mode 1**, 35 × 35 = 1225 pixels, ~9.9 KB at 1024-bit keys) or the compact per-container square (**Mode 2**, 21 × 21 = 441 pixels, ~3.6 KB), **Mode 3** scales the three-region budget by the Gauss-circle ratio (2/π ≈ 63.66% of the **Mode 1** raw floor, yielding a 698-pixel floor and a 28 × 28 = 784-pixel container or ~6.4 KB wire floor at 1024-bit keys — 35.8% smaller than **Mode 1** while keeping 261 pixels per region and ≥ 385 bytes of guaranteed DRBG residue, or 602 bytes at the 698-pixel floor). At the same time, **Mode 3** replaces standard integer division in **Layer I** with tapered 64-bit posit arithmetic and an exact 512-bit quire accumulator: each region derives its own secret circle constant π and exponent regime from the session seed and slices the region along discrete semicircle chords (wider near the center, thinner near the poles). Because the arithmetic precision, rounding boundaries, and circle constant itself are secret-dependent and non-associative across quire projections, an attacker cannot formulate a linear, polynomial, or IEEE-754 floating-point solver model against the pixel trajectory, achieving near **Mode 1** combinatorial security at more than a third less wire overhead.

All three modes converge to identical dimensions once payload volume exceeds the floor. Decoders parse `W` and `H` directly from the frame header: **Mode 1** and **Mode 2** share the same integer **Layer I** trajectory derivation and cross-decrypt each other's ciphertexts without mode configuration, whereas **Mode 3** switches **Layer I** to the Gauss-Posit chord schedule and requires explicit mode selection (`Mode = 3` in pipeline configuration or `ContainerMode = 3` stored in the session blob).

**Decryption.** After the 32-byte prefix, the header `[main_nonce][W][H]` is parsed, and the container is split into thirds. Three parallel goroutines invert the **Layer I** sub-region trajectories (`0x05`) and the Pixel Barrier (noise strip, inverse rotation, and XOR unmask; on MAC Authenticated surfaces, the MAC is verified over the full decoded capacity strictly before COBS decoding) and COBS-decode the lane payloads. The leading interlock-nonce fragments are reassembled, the **Layer II** cross-lane chunk-slot shifts (domain tag `0x06`) are inverted, the 48-bit (or 168-bit under `Interlock = "168"`) chunks are reconstructed from the three lanes using mask triples derived from `lockSeed` and `interlock_nonce`, and the 4-byte length prefix is removed to restore the exact original plaintext.

## 6. Under Normal Use: Attack Resistance Summary

Under standard operation with a PRF-grade hash and CSPRNG nonces:

| Attack | What happens | Barrier status |
|---|---|---|
| **COA** (ciphertext only) | Attacker sees random bytes; hash outputs are unobservable | Intact |
| **KPA** (known plaintext) | Container byte values remain unknown; per-chunk permutation is secret | Intact |
| **CPA** (chosen plaintext) | Fresh nonces produce independent configurations; zero cross-message correlation | Intact |
| **CCA** (chosen ciphertext) | Core ITB and MAC + Silent Drop expose no oracle (see [SECURITY.md § 1 note 1](SECURITY.md#1-itb-composition-modes)) | No oracle exists |

Under passive observation (COA, CPA), the barrier absorbs hash outputs. For Partial KPA and Full KPA analysis see [§ 7](#7-byte-splitting-why-byte-analysis-does-not-work) and [§ 8](#8-full-kpa-prf-assumption), and see [SECURITY.md § 3](SECURITY.md#3-attack-resistance-summary) for the complete attack resistance table.

## 7. Byte-Splitting: Why Byte Analysis Does Not Work

Because `gcd(7, 8) = 1` (7 data bits per channel, 8 bits per byte), plaintext bytes never align with channel boundaries. Every lane byte is split across 2 adjacent 7-bit channels with independent XOR masks.

An attacker knowing an isolated byte value (such as a JSON delimiter `{` or a fixed protocol header field) cannot analyze it on a single channel because each channel mixes bits from two adjacent bytes. Whenever neighboring bytes are unknown (Partial KPA), per-channel candidate formulation is blocked before hash inversion can even be attempted; when all adjacent bytes are known (Full KPA), defense rests on the four-factor closure in [§ 8](#8-full-kpa-prf-assumption) (see [Proof 4a](PROOFS.md#proof-4a-multi-factor-full-kpa-resistance) and [SCIENCE.md § 2.10](SCIENCE.md#210-byte-splitting-property)).

## 8. Full KPA (PRF Assumption)

Full KPA (where the attacker knows the entire plaintext) is the standard cryptographic baseline:

| Condition | Result |
|---|---|
| Full KPA + invertible primitive | Rank Barrier permutation, **Layer I/II** desynchronization (`0x05`/`0x06`), and multi-seed coupling foreclose SAT-based seed recovery at instance formulation. Bitwuzla does not recover the true seed even under maximum-peek regimes (see [REDTEAM.md § FNV-1a lo-lane SAT](REDTEAM.md#fnv-1a-lo-lane-sat--architecturally-foreclosed)). |
| Full KPA + PRF (non-invertible) | Inversion is infeasible. Work factor reduces to brute-force: `P × 2^(2·keyBits)` (Core ITB) or `P × 2^keyBits` (MAC + Reveal), plus per-chunk mask space (≈ 2^70.20 per 48-bit chunk, or ≈ 2^258.60 per 168-bit chunk under `Interlock = "168"`) and **Layer I/II** trajectory and slot spaces. |

Without the barrier, an attacker could test 56 candidates per pixel, invert the hash to recover candidate seeds, and verify across pixels. Under a PRF, candidate verification is infeasible. Under an invertible primitive, the Rank Barrier and **Layer I/II** permutations remove the fixed position-to-lane and slot-to-pixel mappings needed to verify on a second pixel.

**Four-factor Full KPA defense.** Under a non-invertible PRF, Full KPA resistance combines four independent factors ([Proof 4a](PROOFS.md#proof-4a-multi-factor-full-kpa-resistance)), with byte-splitting (`gcd(7, 8) = 1`, [§ 7](#7-byte-splitting-why-byte-analysis-does-not-work)) acting as a 5th factor under Partial KPA:

1. **PRF non-invertibility** — candidate hash outputs cannot be verified against seeds without knowledge of the seed.
2. **Rank Barrier per-chunk mask permutation and Layer II cross-lane slot desynchronization** — each 48-bit chunk is partitioned across lanes via a mask drawn from `≈ 2^70.20` balanced partitions (or `≈ 2^258.60` per 168-bit chunk under `Interlock = "168"` on a 512-bit primitive), and the `M` chunk slots of `(p0, p1, p2)` are cyclically shifted by distinct offsets (`0x06`, `β_0 ≠ β_1 ⟹ Σ_0(j) ≠ Σ_1(j)`, multiplying single-chunk cross-lane slot matching by `M^3`; see [§ 12](#12-the-desynchronized-interlocked-barrier)).
3. **startPixel isolation and Layer I sub-region trajectory** — three independent, non-transmitted offsets (`0x02`) and dynamic sub-region trajectory schedules (`0x05`, spanning `~2^167` at midpoint on the **Mode 2** floor, `~2^187` on the **Mode 3** floor, and `~2^336` at midpoint on the **Mode 1** floor; see [§ 11](#11-startpixels-not-transmitted-not-recoverable) and [PROOFS.md](PROOFS.md)) must be resolved without feedback.
4. **Pixel Barrier ambiguity** — 7 rotations × 8 noise positions maintain 56 equiprobable candidates per pixel at 1:1 signal/noise.

**Full KPA under state-width starvation or unanchored cascade inversion.** Whereas standalone `(input, output)` primitive invertibility (such as GF(2)-linear `CRC128` or T-function `FNV-1a`) remains blocked because intermediate hash outputs never appear on the wire and the 128-bit Feistel-like fold, combinadic unranking, and **Layer I/II** desynchronization foreclose equation formulation ([FAQ.md](FAQ.md) Questions 4–6), state-width starvation (collapsing channel masks and rank entropy, [FAQ.md](FAQ.md) Questions 1–3) or a hypothetical unanchored end-to-end cascade key recovery would collapse the construction (see [Proof 4a](PROOFS.md#proof-4a-multi-factor-full-kpa-resistance)): the Pixel Barrier through direct seed recovery, and the Rank Barrier through `lockSeed` recovery. Formal asymptotic seed-recovery bounds therefore remain PRF-conditional. Within partial PRF weakness, occasional or sporadic inversion events are absorbed — the architectural obstacles generate a false-positive distribution that hides true candidates. Systematic partial inversion is not absorbed; the architecture elevates computational cost but does not eliminate the attack. No such systematic weakness is currently known.

## 9. Nonce Reuse: A Usage Precondition, Not an Absorbed Threat

The construction utilizes two independent nonces: `main_nonce` (governing per-pixel and per-region derivations under `0x02` and **Layer I** `0x05`) and `interlock_nonce` (governing per-chunk mask selections under `0x03` and **Layer II** cross-lane slot permutations under `0x06` via `0x04`). Both are generated internally from `crypto/rand` and enforced distinct. Reaching a caller-forced reuse condition through the shipped API is prevented by internal CSPRNG generation, so reuse can only be simulated in the lab via test overrides.

At the default 512-bit width, birthday collision on either slot requires ~2^256 messages. Within one message (64 MB cap, about 2^23.4 chunks of 48 bits) a repeated per-chunk mask is expected with probability ~2^-24 (or under `Interlock = "168"`, at most 3,195,661 ≈ 2^21.61 chunks of 168 bits across a ≈ 2^258.60 mask space, where within-message mask repetition probability drops to ~2^-216.4). Simultaneous collision on both slots requires a CSPRNG hardware failure.

Three collision scenarios exist in lab testing:

- **Scenario A — dual-slot collision:** Both nonces repeat. All derivations repeat (mask triples, **Layer II** slot shifts, rotations, XOR masks, start pixels, **Layer I** sub-region trajectories).
- **Scenario B — main-only collision:** `main_nonce` repeats, `interlock_nonce` is fresh. Pixel configs and **Layer I** trajectories repeat, but Rank Barrier mask permutations and **Layer II** slot shifts re-randomize.
- **Scenario C — interlock-only collision:** `interlock_nonce` repeats, `main_nonce` is fresh. Rank Barrier mask permutations and **Layer II** slot shifts repeat, but pixel configs and **Layer I** trajectories re-randomize.

**Empirical verdict: plaintext recovery is null across all scenarios at tested sample sizes** (see [REDTEAM.md § Nonce reuse](REDTEAM.md#nonce-reuse-lab-only)). Even in Scenario A, the container XOR exposes data only up to the Rank Barrier's per-chunk permutation and **Layer I/II** permutations ([§ 12](#12-the-desynchronized-interlocked-barrier)): zero bytes are recovered across both random and near-identical plaintext pairs.

**Demasking is not plaintext recovery.** In a stream cipher, `C1 ⊕ C2` directly yields `P1 ⊕ P2`. In ITB, raw ciphertext XOR carries the difference of independent DRBG containers along with per-pixel rotations and XOR masks, and does not reduce to plaintext XOR. A dedicated demasker that strips these layers exposes only the raw PRF hash-output stream up to the barrier permutation, never plaintext bits. On the shipped wire, the per-chunk permutation and **Layer II** cross-lane slot desynchronization remove the demasking anchor entirely — the lane and slot assignments remain unobservable per-chunk and per-lane secrets protected by the two-stage cascade fill ([§ 12](#12-the-desynchronized-interlocked-barrier)).

## 10. CCA: Reveals Only Noise, Not Data

Under CCA (chosen ciphertext with MAC verification feedback), bit-flipping reveals noise bit positions (3 bits per pixel from `noiseSeed`). Because of 8-seed isolation:

- **noiseSeed config** — revealed via CCA.
- **dataSeed configs** (rotation + 56 XOR bits per region) — independent, zero leak.
- **startSeed configs** (`startPixels` under `0x02` and **Layer I** sub-region trajectory schedules `Π_r` under `0x05`) — independent, zero leak.
- **lockSeed** (per-chunk Rank Barrier permutation channel under `0x03` and **Layer II** cross-lane slot desynchronization `Σ_0, Σ_1, Σ_2` under `0x06`) — independent, zero leak.

With noise positions known, candidate configurations drop from 56 to 7 per pixel (rotation unknown). Without an invertible hash, the attacker cannot verify candidates, and the per-chunk permutation remains unobservable.

**DRBG residue in data positions (Theorem 10).** Stripping noise bits exposes 7 data bits per channel, but these contain a mixture of encrypted payload and encrypted DRBG fill bytes, processed identically by `dataSeed`. Because containers enforce dimensions `(s+1) × (s+1)` where `s = ⌈√totalPixels⌉` and `totalPixels` satisfies the ambiguity floor `MinPixels = ⌈keyBits / log₂(7)⌉`, capacity strictly exceeds payload: `gap ≥ (2s + 1) × 7 bytes > 0` ([Proof 10](PROOFS.md#proof-10-guaranteed-drbg-residue-no-perfect-fill), [SCIENCE.md § 2.9](SCIENCE.md#29-guaranteed-drbg-residue-theorem-10)). At 1024-bit keys (`MinPixels = 365`), **Mode 1** (per-region, `3 × 365 = 1095` pixels, `s = 34`, container `35 × 35 = 1225` pixels) yields `gap ≥ 483 bytes`; **Mode 2** (per-container, `totalPixels = 365`, `s = 20`, container `21 × 21 = 441` pixels) yields `gap ≥ 287 bytes`; **Mode 3** (Gauss-Posit, inscribed-circle floor `698` pixels, `s = 27`, container `28 × 28 = 784` pixels) yields `gap ≥ 385 bytes` (`602 bytes` at the `698`-pixel floor). The attacker cannot distinguish payload from fill without `dataSeed`.

CCA leaks 3/62 ≈ 4.8 % of per-pixel configuration, reducing brute-force complexity from `P × 2^(2·keyBits)` to `P × 2^keyBits` (eliminating `noiseSeed`). No plaintext, XOR masks, offsets, or permutations are leaked.

See [SECURITY.md § 2](SECURITY.md#2-cca-oracle-leak-comparison), [SCIENCE.md § 2.8](SCIENCE.md#28-cca-leak-upper-bound-theorem-6), and [Proof 10](PROOFS.md#proof-10-guaranteed-drbg-residue-no-perfect-fill).

## 11. startPixels: Not Transmitted, Not Recoverable

Each region's `startPixel` (`0x02`) and its **Layer I** sub-region trajectory schedule (`0x05`) are derived in registers from its `startSeed` and `main_nonce` via ChainHash. Offsets and sub-region boundaries are neither transmitted nor stored, adding zero bytes to the wire container.

Each region `r ∈ {0, 1, 2}` is partitioned into `K_r ∈ [6, 10]` (**Mode 2** and **Mode 3** floors, `P_r < 365`) or `K_r ∈ [8, 16]` (**Mode 1** floor, `P_r ≥ 365`) disjoint sub-regions with telescopic boundary jitter (`∑ M_{r,k} = P_r`), Fisher-Yates sub-region visit order `τ_r ∈ S_{K_r}`, and independent local starting pixels `s_{r,k} ∈ [0, M_{r,k})` (or Gauss-Posit semicircle chords in **Mode 3**). Across the three regions at 1024-bit container floors, the trajectory space spans `~2^167` configurations at midpoint `K_r = 8` in **Mode 2** (`21 × 21 = 441` px), `~2^187` at midpoint `K_r = 8` in **Mode 3** (`28 × 28 = 784` px), and `~2^224`–`2^445` (midpoint `~2^336` at `K_r = 12`) in **Mode 1** (`35 × 35 = 1225` px); see [PROOFS.md § Proof 4a](PROOFS.md#proof-4a-multi-factor-full-kpa-resistance) for exact factorial derivations.

The only theoretical recovery path for an offset is a local CPU cache side-channel. Even if a local cache side-channel discloses the initial entry pixel `Π_r(0)` in all three regions, `> 2^145` (**Mode 2**), `> 2^162` (**Mode 3**), and `> 2^198` (**Mode 1**) trajectory configurations still remain at `K_r = 8`, alongside 7 rotation candidates per pixel and the unobservable per-chunk permutation ([SCIENCE.md § 1.2.1](SCIENCE.md#121-desynchronized-interlocked-barrier), [§ 2.3](SCIENCE.md#23-8-seed-isolation-theorems-3-3a), [lean/README.md](lean/README.md)).

## 12. The Desynchronized Interlocked Barrier

The **Desynchronized Interlocked Barrier** composes the Rank Barrier and the Pixel Barrier in series across two zero-overhead combinatorial desynchronization layers (see [§ 5](#5-triple-ouroboros-three-interleaved-regions) for the end-to-end pipeline flow):

- **Rank Barrier** — a per-chunk keyed permutation over the interleaved payload keyed by `lockSeed` and `interlock_nonce`, paired with **Layer II** cross-lane chunk-slot desynchronization (`0x06`) in two chunk-width modes:
  - **48-bit default mode (`Interlock = "48"` or `""`):** partitions each 48-bit (`6`-byte) chunk into three 16-bit (`2`-byte) lane fragments across `|Ω_chunk| = A · B ≈ 2^70.20` balanced partitions (supported across all primitive widths: 128, 256, and 512 bits).
  - **168-bit strategic mode (`Interlock = "168"`):** partitions each 168-bit (`21`-byte) chunk into three 56-bit (`7`-byte) lane fragments — matching one full 56-bit pixel data payload per region — across `|Ω_chunk,168| = A₁₆₈ · B₁₆₈ ≈ 2^258.60` balanced partitions (requires a 512-bit inner primitive: `areion512` or `blake2b512`).
- **Pixel Barrier** — a per-pixel encoding stage masking each channel byte via channel XOR, 7-position rotation, and noise-bit insertion along the **Layer I** dynamic sub-region trajectory (`0x05`), keyed by `dataSeed` and `noiseSeed`.

Rank Barrier denies a stable bit-to-lane mapping; Pixel Barrier denies a per-byte observation channel. Neither runs in isolation.

### Layer I and Layer II Desynchronization

The two zero-overhead desynchronization layers remove positional alignment across both pixels and pre-COBS lane slots ([SCIENCE.md § 1.2.1](SCIENCE.md#121-desynchronized-interlocked-barrier), [PROOFS.md](PROOFS.md), [lean/README.md](lean/README.md)):

- **Layer I — Sub-Region Pixel Trajectory Desynchronization (domain tag `0x05` on `startSeed1..3`):** Partitions each region `r ∈ {0, 1, 2}` of `P_r` pixels into `K_r ∈ [6, 10]` (**Mode 2** and **Mode 3** floors, `P_r < 365`) or `K_r ∈ [8, 16]` (**Mode 1** floor, `P_r ≥ 365`) disjoint sub-regions with telescopic boundary jitter (`∑ M_{r,k} = P_r`), Fisher-Yates sub-region visit order `τ_r ∈ S_{K_r}`, and independent local starting pixels `s_{r,k} ∈ [0, M_{r,k})` (or Gauss-Posit semicircle chords in **Mode 3**), spanning `~2^167`, `~2^187`, and `~2^336` 3-region trajectories at midpoint across the 1024-bit **Mode 2**, **Mode 3**, and **Mode 1** floors.
- **Layer II — Cross-Lane Slot Desynchronization (domain tag `0x06` on `lockSeed`):** Evaluates `[0x06 ‖ LE64(i) ‖ v]` (`i ∈ {0, 1}`, where `v` is the 4-byte XOR fold of `interlock_nonce`) to shift the `M` chunk slots of `(p0, p1, p2)` by guaranteed distinct offsets (`β_0 ≠ β_1 ⟹ Σ_0(j) ≠ Σ_1(j)`). Every pre-COBS slot `j` mixes fragments from at least two distinct plaintext chunks, preserving 100 % of `|Ω_chunk|` and `|Ω_chunk,168|` while multiplying single-chunk cross-lane slot matching by `M^3` (and combining multiplicatively with **Layer I** into the joint 1-chunk anchor `|Ω| · M^3 · |T_I|` tabulated below).

### Rank Barrier

**Two-stage cascade depth.** Plaintext bits are never mapped to lanes by `lockSeed` directly: first, an intermediate per-message key `K` is derived under domain tag `0x04` over `[0x04 ‖ interlock_nonce]` keyed by `lockSeed`; second, round 1 of every per-chunk rank evaluation (`[0x03 ‖ LE64(groupIdx) ‖ v]`) runs as a dedicated **primer round** seeded with `K` before feeding forward through `lockSeed` session components. The Pixel Barrier operates directly over session components at depth `r = keyBits / width` (4 / 8 / 16 rounds at width 128 for 512 / 1024 / 2048-bit keys; 2 / 4 / 8 at width 256; 1 / 2 / 4 at width 512), without an intermediate key. The Rank Barrier operates at depth `r = 1 + keyBits / width` (5 / 9 / 17 rounds at width 128; 3 / 5 / 9 at width 256; 2 / 3 / 5 at width 512), where the additional primer round binds every chunk's rank to `interlock_nonce` before session components are mixed.

**48-bit mask-space cardinality and under-determination (Theorem 11).** In the default 48-bit mode (`Interlock = "48"`), choosing 16 of 48 bits for lane 0 (`A = C(48, 16) = 2,254,848,913,647`, `log₂ ≈ 41.04`) and 16 of the remaining 32 bits for lane 1 (`B = C(32, 16) = 601,080,390`, `log₂ ≈ 29.16`, fixing `m2` as the complement) yields ([Proof 11](PROOFS.md#proof-11-48-bit-rank-barrier-mask-space-interlocked-barrier), [SCIENCE.md § 2.15](SCIENCE.md#215-48-bit-and-168-bit-rank-barrier-mask-spaces-theorem-11)):

- `A · B = 1,355,345,464,406,015,082,330` (log₂ ≈ 70.20).

Under the PRF assumption, recovered masks carry zero information about neighboring chunks: even granting an attacker all 48 known plaintext bits of a chunk under Full KPA, the number of preimages per mask triple is `⌊2^128 / (A · B)⌋ ≈ 2^57.80`, and combined with the Pixel Barrier's 1:1 signal/noise ambiguity the attacker has no ranking signal among the `≈ 2^70.20` masks.

**Two-step reduction and gcd(A, B) anti-collapse (Theorem 12).** Each 128-bit PRF rank maps onto `[0, A) × [0, B)` via two-step division-modulo reduction `idx1 = rank mod B`, `idx0 = ⌊rank / B⌋ mod A` ([Proof 12](PROOFS.md#proof-12-gcda-b-anti-collapse-trap), [SCIENCE.md § 2.16](SCIENCE.md#216-gcda-b-anti-collapse-trap-theorem-12)). The naive alternative `(rank mod A, rank mod B)` is flawed because `gcd(A, B) = gcd(C(48, 16), C(32, 16)) = 66,861 = 3² · 17 · 19 · 23`, which would restrict reachable pairs to `1 / 66,861 ≈ 1.5 × 10⁻⁵` of the space (eroding `log₂ 66,861 ≈ 16.03` bits of entropy). Two-step reduction preserves the full `≈ 2^70.20` space with a relative deviation of ≈ 2^-57.8 per chunk; accumulated linearly over a maximum message of 2^23.42 chunks, deviation is bounded by ≈ 2^-34.4. Detecting this would require ~2^115.6 chunk samples (~2^92 maximum-size messages), far beyond any attainable data budget.

### 168-Bit Interlocked Barrier (`Interlock = "168"`): Trans-Landauer Margin for 512-Bit Primitives

When ITB is configured with a 512-bit inner primitive (`areion512` or `blake2b512`), callers can enable the **168-bit Interlocked Barrier** (`Interlock = "168"`). Rather than slicing a 512-bit cascade output into four 128-bit ranks for 48-bit chunks, the 168-bit mode consumes the entire 512-bit digest (`2^512`) to key a single **168-bit (`21`-byte) chunk** partitioned into **three 56-bit (`7`-byte) lanes** — delivering one complete 56-bit pixel payload to each of the three regions in lockstep.

Choosing 56 of 168 bits for lane 0 (`A₁₆₈ = C(168, 56) ≈ 1.80 × 10⁴⁵`, `log₂ ≈ 150.33`) and 56 of the remaining 112 bits for lane 1 (`B₁₆₈ = C(112, 56) ≈ 3.91 × 10³²`, `log₂ ≈ 108.27`) yields `|Ω_chunk,168| = A₁₆₈ · B₁₆₈ ≈ 7.03 × 10⁷⁷` (`≈ 2^258.60`) balanced partitions per 21-byte chunk (see [PROOFS.md § Proof 11](PROOFS.md#proof-11-48-bit-rank-barrier-mask-space-interlocked-barrier) and [lean/README.md](lean/README.md) for exact integers). Even on a single 21-byte chunk, `≈ 2^258.60` exceeds the 256-bit key space of AES-256 by more than `6×`, and across `C` independent chunks `(A₁₆₈ · B₁₆₈)^C` overtakes `2^512` at `C = 2` chunks (`42` B), `2^1024` at `C = 4` chunks (`84` B), and `2^2048` at `C = 8` chunks (`168` B). Each mask triple has `⌊2^512 / (A₁₆₈ · B₁₆₈)⌋ ≈ 2^253.40` 512-bit preimages, and a balanced 21-byte crib leaves `≈ 2^90.6` (`≈ 2^90`) compatible mask triples.

As in 48-bit mode, two-step reciprocal reduction `(Q, idx1) = divmod(R₅₁₂, B₁₆₈)`, `idx0 = Q mod A₁₆₈` avoids the naive double-modulo CRT collapse caused by `gcd(A₁₆₈, B₁₆₈) = 10,078,335,949,946,663,736` (`log₂ ≈ 63.13`, `1 / gcd ≈ 9.9 × 10⁻²⁰`), which would otherwise destroy `63.13` bits of entropy. Because `2^512` is `2^253.40 ×` larger than `A₁₆₈ · B₁₆₈`, per-chunk bias drops to `≈ 2^-253.4` (`≈ 2^-231.8` across a maximum 64 MiB message of `3,195,661 ≈ 2^21.61` chunks), requiring `1 / ε² ≈ 2^506.8` chunk samples (`~2^485` maximum-size messages) to distinguish from ideal uniform — exceeding the **Landauer thermodynamic bound** (`~2^306 ≈ 10⁹²` irreversible bit operations from the mass-energy of the observable universe at `2.725 K`) by **more than 200 orders of magnitude in base 2** (`> 2^200×`, or `> 10⁶⁰×`).

### Pixel Barrier

**Per-pixel absorption.** Each pixel packs 56 data bits into 8 channel bytes labelled with the RGBWYOPA mnemonic (Red, Green, Blue, White, Yellow, Orange, Purple, Alpha) as byte-unit positions, unrelated to image processing. Each channel undergoes 7-bit XOR masking, 7-position rotation, and insertion of an original DRBG noise bit at `noisePos`.

**The absorption guarantee:** Under passive observation across unknown uniform plaintext, for any observed byte `v` and hash output `h`, `P(v | h) = 1/256` ([Proof 1](PROOFS.md#proof-1-information-theoretic-barrier)); conditional on fixed lane data `d`, each of the two candidate byte values occurs with probability `P(v | h, d) = 1/2`. Because the noise bit originates from the DRBG, observations do not uniquely determine hash outputs.

**Why KPA candidates do not break the barrier.** An attacker can calculate 56 candidate hash outputs per pixel, but all 56 are equally consistent with observation. Without ChainHash inversion, the candidate space cannot be narrowed. Under an invertible primitive, inverting ChainHash bypasses the Pixel Barrier's per-pixel ambiguity, but the Rank Barrier's per-chunk permutation and **Layer I/II** desynchronization remain — the mapping from plaintext bits to lane positions, chunk slots, and sub-region pixels is a hidden secret that primitive inversion cannot recover. Direct guessing of the 62-bit-per-pixel configuration map requires `2^(62·P)` attempts (≈ 2^75950 for 1024-bit keys), far exceeding the key space.

**Cost and mandatory enforcement.** Combinadic unranking and bit partitioning execute on 8/16-lane AVX-512F, AVX2, and ARM64 NEON/SVE2 SIMD kernels with constant-time branchless fallbacks on all other targets (see [KERNELS.md](KERNELS.md)), while **Layer I** (`0x05`) and **Layer II** (`0x06`) operate over contiguous sub-region slices and pre-COBS lane buffers. Every exported entrypoint of the `itb.Encrypt3x*` and `Decrypt*` families, as well as all shipped `Triple` profiles, routes through the **Desynchronized Interlocked Barrier** unconditionally (`Interlock = "48"` by default, or `Interlock = "168"` when configured on 512-bit primitives via `itb.Config`, `triple.Opts`, `triple.Profile`, or `itb.Blob512Opts`).

## 13. Quantum Resistance

The barrier relies on information absence rather than computational hardness alone: an observation contains insufficient information to reconstruct hash outputs. This property is computation-model-independent:

- **Grover** — requires a verification oracle. Core ITB and MAC + Silent Drop offer no oracle; `noiseSeed` and `dataSeed` must be searched jointly, with start pixels and **Layer I** sub-region trajectories enumerated and per-chunk masks and **Layer II** slot permutations unobservable.
- **Simon** — requires periodic structure. Aperiodic nonces (up to 512 bits) ensure fresh configurations per message.
- **BHT** — requires observable collisions. The random container and per-pixel encoding ambiguity absorb collisions before observation.
- **Q2 superposition queries** — precluded; every encryption draws two fresh internal CSPRNG nonces (`main_nonce` and `interlock_nonce`), collapsing chosen-plaintext superposition coherence across Core ITB and MAC modes alike, and the MAC verification oracle is strictly classical and network-bounded (see [POSTQUANTUM.md § 1.2](POSTQUANTUM.md#12-q1-vs-q2-quantum-attack-models)).

At 1024-bit key sizes, search complexities vastly exceed foreseeable quantum limits.

Unlike AES or ChaCha20 where testing a key takes nanoseconds on a single block, testing an ITB key requires decrypting the entire container:

## 15. Barrier and PRF: Symbiosis

The barrier and the PRF primitive protect each other:

- **PRF protects the barrier:** Non-invertibility prevents an attacker from resolving the 56-to-1 per-pixel ambiguity, the **Layer I** sub-region trajectories, and the per-chunk ≈ 2^70.20 (or ≈ 2^258.60 under `Interlock = "168"`) mask space and **Layer II** cross-lane slot permutations.
- **Barrier protects the PRF:** Two pixels with identical hash outputs receive different container bytes from the DRBG, so their observed bytes differ. The collision is absorbed. The inseparable Interlocked Barrier absorbs a broad spectrum of primitive weaknesses beneath its composite layers: output collisions, statistical non-uniformities, structural biases, and trapdoor effects (such as the BEA-1 partition trapdoors and Malicious SHA-1 chosen-constants collision trapdoors documented in [HARNESS.md](HARNESS.md)) are masked by random container noise insertion, independent rotation, **Layer I** sub-region trajectory routing, and per-chunk lane and **Layer II** slot scrambling. Even below-spec stress primitives exhibit zero observable leakage when enveloped by the full barrier.
- **ChainHash architecture resists MITM:** Sequential component mixing ensures that partial key compromise reveals nothing about adjacent components.

Together, non-invertibility blocks inversion, and the barrier absorbs primitive defects. Under passive observation, the composite cipher behaves as an ideal random permutation. Under active cryptanalysis and Full KPA, formal asymptotic seed-recovery bounds remain computational and PRF-conditional, while instance-formulation and solver resistance arise jointly from the PRF cascade and the **Desynchronized Interlocked Barrier** ([§ 8](#8-full-kpa-prf-assumption)).

## 16. Oracle-Free Deniability

Decryption with an incorrect seed constellation produces uniform random bytes with no distinguishing signal:

- **No magic bytes or file headers:** Wire containers consist solely of `[prefix(32)][main_nonce][W][H][container]` records — one for a Single Message, one per chunk for a stream, every chunk having the same record shape as a Single Message wire — each prefix being CSPRNG output.
- **No plaintext length header:** Length metadata is encrypted inside the container across chunk boundaries.
- **Encrypted null terminator:** COBS termination is hidden within the ciphertext.
- **No padding:** Rotation and XOR masking provide confidentiality without padding markers.
- **Uniform failure:** Wrong seeds produce pseudorandom bytes indistinguishable from random data.
- **Silent drop:** MAC failure drops silently without leaking verification feedback in Core ITB and MAC + Silent Drop modes (under MAC + Reveal, CCA interaction exposes only the 3-bit noise position oracle, leaving plaintext and other seeds unobservable).

Deployments requiring full oracle-free deniability operate under Core ITB or MAC + Silent Drop, ensuring incorrect keys or altered ciphertexts produce zero verification feedback.

## 17. Custom Primitives

ITB allows custom hash primitives through two native extension points:

1. **Direct closures at the Low-Level surface:** Pass `itb.HashFunc{N}` and `itb.BatchHashFunc{N}` closures directly to `*Cfg` functions.
2. **Registration via `hashes.Register`:** Add a primitive to the runtime registry by name, enabling use within `triple.Profile` and `triple.Init`.

**Key constraints:**
- Custom registration is a Go-native feature only; FFI bindings consume the frozen C ABI and do not expose dynamic primitive registration.
- Registration is immutable: names cannot be overwritten or redefined once registered.

For complete examples and implementation guidelines, see [README.md § Custom user-supplied hashes](README.md#custom-user-supplied-hashes) and [hashes/README.md](hashes/README.md).

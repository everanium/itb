## ITB Assembly Kernels

The shipped `_amd64.s` kernels target a modern x86-64 baseline. The exact CPU feature each kernel needs is detected once at package init by `internal/cpuid` (`github.com/klauspost/cpuid/v2` on amd64, `golang.org/x/sys/cpu` on arm64) and dispatched from there:

| Kernel | Required CPU feature | Runtime capability flag |
|---|---|---|
| Interlocked Barrier — scalar apply (per-chunk `Chunk48Lock` / `Unchunk48Lock`) | BMI2 (PEXTQ / PDEPQ) | `interlock.HasBMI2` |
| Interlocked Barrier — batched scalar apply (n consecutive chunks per call, mask taken as a memory operand; bit-exact with n per-chunk calls, amortises the Go-loop overhead) | BMI2 (PEXTQ / PDEPQ) | `interlock.HasChunk48Batch` |
| Interlocked Barrier — AVX-512F rank-unrank | AVX-512F (VPERMT2Q, VPCMPUQ, VPTESTMQ, mask-merged VPSUBQ / VPORQ, VPTERNLOGQ / VPSLLQ / VPSRLQ constant synthesis on ZMM; scalar PDEPQ remap tail in-place over `out`, `$0-32` frame) | `interlock.HasAVX512RankMask` |
| Interlocked Barrier — AVX-512F 16-lane rank-unrank (the 8-lane kernel run as two interleaved batches for the batch-16 PRF fill; two 8-lane passes via `ITB_FORCE_INTERLOCK_TIER=avx512x8`) | AVX-512F (VPERMI2Q / VPERMT2Q row select, VPTESTMQ predicate; scalar PDEPQ remap tail in-place over `out`, `$0-32` frame) | `interlock.HasAVX512RankMask` + `interlock.UseUnrank16` |
| Interlocked Barrier — AVX2 rank-unrank | AVX2 + BMI2 (VPERMD, VPCMPEQQ, VPCMPGTQ predicated ops on YMM; scalar PDEPQ remap tail in-place over `out`, `$0-32` frame) | `interlock.HasAVX2RankMask` |

| ChaCha20 (RFC 8439) CTR keystream XOR (`internal/chacha20ctr`) — NEON 4-block / 1-block keystream XOR (`chacha20ctr_arm64.s`; auto-selected on every ARMv8-A host) | Advanced SIMD | `chacha20ctr.HasNEON` |

Every shipped primitive fills the Interlocked Barrier through its batch-16 fused cascade kernels; the four-lane and single-lane arms of the same kernel families serve the fill below the batch-16 hook.

Across the kernel families: all six Interlocked Barrier assembly files (`interlockasm48_{,x16_,avx2_,batch_}amd64.s`, `interlockasm48_{neon,sve2}_arm64.s`) execute with `NOSPLIT`, `$0` stack frames, and zero stack spills (the unrank kernels stage `m1Local` in `out[1]` and `remaining` in `out[2]` and overwrite them in-place during the remap tail), while 128-bit rank reduction (`splitRank48Recip`) runs via constant-time 64-bit reciprocal multiplications (`MULQ` / `UMULH` with `interlockB48Recip` and `interlockA48Recip`) across all architectures without hardware `DIVQ`. Every Areion-SoEM kernel keeps `K1`, `k2`, and `w = K1 ⊕ k2` 100% register-resident across all five tiers (`zmm`, `ymm`, `vex`, `sse`, `neon`) with zero subkey or whitening stack spills, using 3-operand VAES (`VAESENC b, a, b` at width 512) and in-place NEON round bodies (`AESE zero, a; AESMC a, t`). The BLAKE2b / BLAKE2s / BLAKE3, SipHash-2-4, and ChaCha20 generators elide `"zero"` message-word additions and `size == 0` `D[idx]` slot/ternary folds at compile time across all five tiers (`avx512`, `avx2`, `neon`, `gpr_amd64`, `gpr_arm64`); on `avx512`, BLAKE2b / BLAKE2s / BLAKE3 keep multi-block chaining state `H[0..7]` in `X24..X31` / `Y24..Y31` / `Z24..Z31` with zero secret stack slots (`NOSPLIT` across all 24 `blake2b` `avx512` and all 8 `blake2s` `avx512` kernels, plus a 728-byte `NOSPLIT` budget covering the single-block `blake2b` `avx2` 4-lane, `blake2s` `13x8_avx2`, and `blake3` `{13,20,36}x8_avx2` kernels), while ChaCha20 builds `K ⊕ component ⊕ h` directly in `v[4..11]` in registers across `avx512`, `avx2`, and `neon` and caches up to 12 slot words in `X20..X31` / `Y20..Y31` (`$0-44` frame on `13x8` fill) and up to 10 slot words in `V16..V23, V26..V27` on `neon`. SipHash-2-4 `gpr_x1_amd64` executes with a `$0-32` zero-byte stack frame at every shape (`13, 20, 36, 68`), and `neon_x4` caches up to five message words in `V12..V15, V26..V31` (zero in-loop stack loads at shapes `13, 20, 36`).

### CTR Keystream XOR & 4-Lane Batch-PRF Kernels

Beyond the inner pixel and Rank Barrier cascades, the counter-mode keystream XOR kernels in `internal/blake2bctr`, `internal/blake2sctr`, `internal/blake3ctr`, `internal/siphash24`, and `internal/chacha20ctr` (along with 4-lane batched PRF kernels in the first four) pair with the batched `Areion-SoEM-256 / 512` and hardware `AES-128-CTR` paths in `ctr` and `internal/hashprf`. Together they serve six runtime consumers: `ctr` (resettable counter-mode stream ciphers), `wrapper` (outer cipher CTR encryption), `parallax` (multi-cipher CTR keystream palettes), `internal/drbg` (CSPRNG-seeded container and interlock-lane noise fill), `internal/hashprf` (single-input and 4-lane batched PRF evaluation via `NewBatchRawWithClose`), and `kdf` (NIST SP 800-108 counter-mode and XChaCha20 KDF expansion). Every assembly entry point executes with `NOSPLIT` and a `$0` stack frame (100% register-resident working state with zero stack spills) and zeroes all touched vector and general-purpose registers before `VZEROUPPER` / `RET`:

- **`internal/blake2bctr` (`BLAKE2b-256 / 512`):** `InitKey256` and `InitKey512` precompute the 8-word chaining state `hKey[0..7]` after compressing the 128-byte zero-padded RFC 7693 key block (`t0 = 128, f0 = 0`), reducing every 24-byte (`16B nonce || LE64(counter)`) CTR block (`t0 = 152, f0 = ^0`) to a single 12-round compression block with `m[3..15] == 0` (eliding `13/16` message words at compile time in the `G_EVEX`, `GX_EVEX`, `GY_EVEX`, and `GZ_EVEX` macros). `AVX-512VL` (`blake2bctr_amd64.s`) runs 4-lane `YMM` (`Y0..Y15` working state, `Y16..Y23` broadcast `hKey[0..7]`, `Y24..Y26` message words `m0..m2`, `VPRORQ` hardware rotates, `VPTERNLOGQ` feed-forward); `AVX2` runs 4-lane `YMM` in a `$0` stack frame by holding `v[15]` in `R8..R11` and swapping `v[12]` (`Y12`) into `R8..R11` during the diagonal step (`SWAP_Y12`); `NEON` (`blake2bctr_arm64.s`) runs 2 lanes per pass (`V.D2` state in `V0..V15`, preloaded `hKey` and `IV` in `V20..V31`, `VSHL`+`VSRI` and `VREV64` rotates, `VZIP1`/`VZIP2` interleave).
- **`internal/blake2sctr` (`BLAKE2s-256`):** `InitKey` precomputes `hKey[0..7]` (`[8]uint32`) after compressing the 64-byte zero-padded RFC 7693 key block (`t0 = 64, f0 = 0`), reducing every 24-byte CTR block (`t0 = 88, f0 = 0xffffffff`) to a single 10-round compression block with `m[6..15] == 0` (eliding `10/16` message words at compile time). `AVX-512VL` (`blake2sctr_amd64.s`) runs an 8-block `YMM` loop + 4-block `XMM` tail (`VPRORD` rotates, `VPTERNLOGD` feed-forward, and exact 64-bit `counter + lane` split into `m[4]` low and `m[5]` high via `VPADDQ` + `VPSHUFD` + `VPUNPCKLQDQ`/`VPUNPCKHQDQ`); `AVX2` runs a 4-block `XMM` loop in a `$0` frame (`v[15]` in `(R12, R13)` swapped with `X12` for diagonal rounds, and 64-bit counter low/high words parked in `R8..R9` and `R10..R11`); `NEON` (`blake2sctr_arm64.s`) runs a 4-block `V.S4` loop (GPR `ADD`/`MOVWU`/`LSR`/`ORR` 64-bit counter split into `V28`/`V29`, `VREV32` / `VTBL` / `VSHL`+`VSRI` rotates, `VZIP1`/`VZIP2` transpose).
- **`internal/blake3ctr` (`BLAKE3`):** Evaluates a single 7-round keyed compression block (`cv = keyWords[0..7]`, `t = 0`, `blockLen = 24`, `flags = CHUNK_START | CHUNK_END | ROOT | KEYED_HASH = 0x1B`) with `m[6..15] == 0` (`10/16` message words zero-elided at compile time). `AVX-512VL` (`blake3ctr_amd64.s`) runs an 8-block `YMM` loop + 4-block `XMM` tail (`VPRORD` rotates, broadcast key words and nonce/counter state across `Y16..Y31`); `AVX2` runs a 4-block `XMM` loop in a `$0` frame (`v[15]` in `(R12, R13)` swapped with `X12`, counter words in `R8..R11`); `NEON` (`blake3ctr_arm64.s`) runs a 4-block `V.S4` loop.
- **`internal/siphash24` (`SipHash-2-4-128`):** `InitCTRState` pre-absorbs the constant `m0 = nonceHi` (2 SipRounds) into `vInit[0..3]`, reducing each 16-byte CTR block to 12 SipRounds (`m1 = nonceLo ^ (counter + b)`, padding word `16 << 56`, `0xee` low-half finalization, `0xdd` high-half finalization). `AVX-512VL` (`siphash24_amd64.s`) runs an 8-block dual-`YMM` loop + 4-block `YMM` + 1..3-block `XMM` tail (`VPROLQ` rotates, `VPTERNLOGQ` finalization, `VPUNPCKLQDQ`/`VPUNPCKHQDQ` + `VSHUFI64X2` `(lo, hi)` lane interleave); `AVX2` runs a 4-block `YMM` loop + 1..3-block `XMM` tail (`VPUNPCKLQDQ`/`VPUNPCKHQDQ` + `VPERM2I128` interleave); `NEON` (`siphash24_arm64.s`) runs a 4-block `2×V.D2` loop (`VZIP1`/`VZIP2` interleave).
- **`internal/chacha20ctr` (`ChaCha20 (RFC 8439)`):** `AVX-512VL` (`chacha20ctr_amd64.s`) runs an 8-block `YMM` loop + 4-block `XMM` tail + 1-block `XMM` tail (`VPROLD` `$16/$12/$8/$7` rotates, 8×8 `VPUNPCK*` + `VSHUFI64X2` transpose); `AVX2` runs a 4-block `YMM` loop + 1-block `XMM` tail (`VPUNPCK*` + `VPERM2I128` transpose); `NEON` (`chacha20ctr_arm64.s`) runs a 4-block `V.S4` loop (`VREV32` / `VTBL` / `VSHL`+`VSRI` rotates, `VZIP1`/`VZIP2` transpose).
- **`Areion-SoEM-256 / 512` & `AES-CMAC` CTR paths:** `Areion-SoEM-256 / 512` CTR (`areionCTR` / `hashCTR` via `prfHashCTRBatch` and `internal/hashprf`) evaluates 4-lane batched `SoEM22` (`Areion{256,512}SoEMPermutex4*` in `internal/areionasm` across `VAES ZMM`, `VAES YMM`, `VEX AES-NI`, `SSE AES-NI`, and `ARM64 Crypto AESE/AESMC`) over 24-byte (`16B nonce || LE64(counter)`) inputs with pre-expanded per-lane subkey and whitening tables (`soa.k1b*`, `soa.k2b*`, `soa.wb*`), while `AES-CMAC` (`aescmac` / `aes-128-ctr` in `ctr/`) delegates to hardware `AES-128-CTR` (`crypto/aes` + `crypto/cipher.NewCTR` wrapped in `aesResettable` for zero-allocation counter repositioning).

Cross-referenced to shipping x86 microarchitectures:

- **Intel** — top-tier fused ZMM chain kernels and AVX-512F+VL CTR keystream XOR / 4-lane Batch-PRF kernels (`internal/blake2bctr`, `internal/blake2sctr`, `internal/blake3ctr`, `internal/siphash24`, `internal/chacha20ctr`) are exercised end-to-end from **Rocket Lake (11th-gen, e.g. i7-11700K)** onward. Ice Lake mobile parts carry the required flags but are not the reference host. **Cascade Lake / Cooper Lake and other AVX-512-without-VAES / VBMI SKUs** engage the AVX-512F ARX chain kernels and AVX-512F+VL CTR keystream XOR / 4-lane Batch-PRF kernels for the BLAKE / SipHash / ChaCha20 family plus the VEX XMM AES-NI 4-lane batched kernels for Areion-SoEM (the fused cascade and the batched SoEM of the general and CTR paths) and AES-CMAC, take the VEX 8-lane kernels (eight-pixel stride) for AES-ITB-128 and AES-CMAC, and select pixel-encoder Tier A′ (AVX-512F+BW+VL without GFNI/VBMI). **Haswell through Comet Lake** engage the AVX2 4-lane and 8-lane chain kernels (the eight-pixel stride of the pixel pipeline on every family), the AVX2 `$0`-frame CTR keystream XOR and 4-lane Batch-PRF kernels (`internal/*ctr`, `internal/siphash24`), the AVX2 4-lane interlock rank-mask kernel, the VEX XMM AES-NI 4-lane and 8-lane batched kernels, and pixel-encoder Tier B′ (AVX2 no GFNI).
- **AMD** — top-tier fused ZMM chain kernels and AVX-512F+VL CTR keystream XOR / 4-lane Batch-PRF kernels engage from **Zen 4 onward** (server-class Zen 4 / Zen 5); pixel encoder runs Tier A (GFNI present). **Zen 3** engages the VAES YMM fused ChainHash cascade kernels for AES-ITB-128 and AES-CMAC (four and eight lanes) and for Areion-SoEM, the VAES YMM fused batched SoEM for Areion-SoEM (general and CTR paths), the AVX2 four- and eight-lane BLAKE2s / BLAKE3 / SipHash / ChaCha20 fused ChainHash cascade kernels, the AVX2 four-lane BLAKE2b kernels, the AVX2 `$0`-frame CTR keystream XOR and 4-lane Batch-PRF kernels (`internal/*ctr`, `internal/siphash24`), the AVX2 4-lane interlock rank-mask kernel, and pixel-encoder Tier B′; the pixel pipeline takes the eight-pixel stride on every family. **Zen 1 / Zen 2** carry AES-NI and BMI2 and engage the Interlocked Barrier BMI2 apply kernels, the AVX2 4-lane rank-mask kernel, the AVX2 and VEX AES-NI fused ChainHash cascade kernels, and the AVX2 CTR keystream XOR / 4-lane Batch-PRF kernels. `PEXT` / `PDEP` are microcode-emulated there, with a latency that grows with the mask popcount; every Interlocked Barrier mask has a fixed popcount (see [HWTHREATS.md](HWTHREATS.md)).
- **Older or narrower x86-64 hosts** — build with `-tags noitbasm` to skip the ITB-native assembly entirely; the upstream primitive libraries' own ASM (`crypto/aes`, `dchest/siphash`, `golang.org/x/crypto`, `zeebo/blake3`) stays engaged. The CGO pixel encoder needs no such tag: on a host without AVX2 it runs its portable C tier, built for baseline x86-64.
- **The `noasm` build tag** — on amd64 the CPU features come from `github.com/klauspost/cpuid/v2`, which reports none under `-tags noasm`; every ITB kernel then takes its scalar path. Output is unchanged, throughput drops.
- **ARM64** — AES-ITB-128 (`internal/aesitbasm/`), the Areion-SoEM permutation (`internal/areionasm/areion_arm64.s`), and AES-CMAC (`hashes/internal/aescmacasm/`) run through `AESE`/`AESMC` on hosts with the ARM Crypto Extension for fused cascade, batch-16 fill, and 4-lane batched SoEM CTR / PRF evaluation, while NEON fused cascade kernels (`hashes/internal/*asm/`) and `$0`-frame NEON CTR keystream XOR / 4-lane Batch-PRF kernels (`internal/blake2bctr`, `internal/blake2sctr`, `internal/blake3ctr`, `internal/siphash24`, `internal/chacha20ctr`) accelerate the BLAKE / SipHash / ChaCha20 primitives. The Interlocked Barrier unrank runs via the 8-lane NEON kernel (`internal/interlock/interlockasm48_neon_arm64.s`), chunk application accelerates via SVE2 BitPerm (`FEAT_SVE_BitPerm` on Graviton 4 / Neoverse V2) or the batched ARM64 16-step set-bit-walk (`pext16` / `pdep16` via `RBIT` + `CLZ` in `internal/interlock/interlockasm48_batch_arm64.go`), and portable Go fallbacks remain available.
- **Every other Go target** — the pure-Go pipeline via `CGO_ENABLED=0` runs on any GOOS / GOARCH the Go compiler supports; throughput drops but correctness is preserved.

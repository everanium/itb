## ITB Assembly Kernels

The shipped `_amd64.s` kernels target a modern x86-64 baseline. The exact CPU feature each kernel needs is detected once at package init by `internal/cpuid` (`github.com/klauspost/cpuid/v2` on amd64, `golang.org/x/sys/cpu` on arm64) and dispatched from there:

| Kernel | Required CPU feature | Runtime capability flag |
|---|---|---|
| Interlocked Barrier — scalar apply (per-chunk `Chunk48Lock` / `Unchunk48Lock`) | BMI2 (PEXTQ / PDEPQ) | `interlock.HasBMI2` |
| Interlocked Barrier — batched scalar apply (n consecutive chunks per call, mask taken as a memory operand; bit-exact with n per-chunk calls, amortises the Go-loop overhead) | BMI2 (PEXTQ / PDEPQ) | `interlock.HasChunk48Batch` |
| Interlocked Barrier — AVX-512F rank-unrank | AVX-512F (VPERMT2Q, VPCMPUQ, VPTESTMQ, mask-merged VPSUBQ / VPORQ, VPTERNLOGQ / VPSLLQ / VPSRLQ constant synthesis on ZMM) | `interlock.HasAVX512RankMask` |
| Interlocked Barrier — AVX-512F 16-lane rank-unrank (the 8-lane kernel run as two interleaved batches for the batch-16 PRF fill; two 8-lane passes via `ITB_FORCE_INTERLOCK_TIER=avx512x8`) | AVX-512F (VPERMI2Q row select, VPTESTMQ predicate; scalar PDEPQ remap tail) | `interlock.HasAVX512RankMask` + `interlock.UseUnrank16` |
| Interlocked Barrier — AVX2 rank-unrank | AVX2 + BMI2 (VPERMD, VPCMPEQQ, VPCMPGTQ predicated ops on YMM; scalar PDEPQ remap tail) | `interlock.HasAVX2RankMask` |
| AES-ITB-128 — VAES ZMM 4-lane fused chain (auto-selected on VAES + AVX-512F hosts) | VAES + AVX-512F | `aesitbasm.FusedHasVAESAVX512` |
| AES-ITB-128 — VAES ZMM 8-lane fused chain (two four-lane state groups per call with interleaved cascade rounds; auto-selected on VAES + AVX-512F hosts for the 128 / 256 / 512-bit nonce-buf shapes and driven by the pixel pipeline's eight-pixel stride; the four-lane ZMM kernels and four-pixel stride via `ITB_FORCE_CHAINHASH_X4=1`) | VAES + AVX-512F | `aesitbasm.FusedHasVAESAVX512X8` (with `aesitbasm.FusedHasVAESAVX512`) |
| AES-ITB-128 — VAES YMM 2-lane-per-register fused chain (auto-selected on VAES + AVX2 hosts without AVX-512F) | VAES + AVX2 | `aesitbasm.FusedHasVAESAVX2` |
| AES-ITB-128 — VEX AES-NI XMM 4-lane fused chain (auto-selected on AES-NI + AVX2 hosts without VAES) | AES-NI + AVX2 | `aesitbasm.FusedHasAVXAESNI` |

| AES-ITB-128 — 8-lane fused chain of the AES-NI tiers below ZMM (four YMM states of two lanes on VAES YMM, eight XMM states on VEX / legacy-SSE AES-NI, cascade rounds interleaved across the states; auto-selected with the tier for the 128 / 256 / 512-bit nonce-buf shapes and driven by the pixel pipeline's eight-pixel stride; two four-lane calls and the four-pixel stride via `ITB_FORCE_CHAINHASH_X4=1`) | as per tier above | `aesitbasm.FusedHasAESNIX8` (with the tier flag) |

| AES-ITB-128 — NEON 4-lane fused chain + batch-16 fill (arm64, auto-selected on ARM Crypto Extension hosts) | ARMv8 Crypto Extension (AESE / AESMC) | `aesitbasm.FusedHasARMAES` / `aesitbasm.HasARMAESX16` |
| AES-ITB-128 — `aesitb128` DRBG noise fill (counter-mode blocks, five AES rounds each; VAES YMM 16 blocks per pass on every VAES host under auto-dispatch, AVX-512F hosts included, since VAES ZMM matches it within run-to-run spread on the hosts measured and YMM keeps the fill off the ZMM register file; VAES ZMM 16 blocks per pass only under `ITB_FORCE_HASH_TIER=avx512` on VAES + AVX-512 hosts; VEX AES-NI XMM 8 blocks on AES-NI + AVX2 hosts without VAES, legacy-SSE AES-NI XMM 8 blocks on the remaining AES-NI hosts, NEON 8 blocks on arm64 Crypto Extension hosts; follows the fused-cascade tier, so `ITB_FORCE_HASH_TIER` overrides it) | as per tier above | `aesitbasm.FusedHasVAESAVX512` / `FusedHasVAESAVX2` / `FusedHasAVXAESNI` / `FusedHasAESNI` / `FusedHasARMAES` |

Every shipped primitive fills the Interlocked Barrier through its batch-16 fused cascade kernels; the four-lane and single-lane arms of the same kernel families serve the fill below the batch-16 hook.

Cross-referenced to shipping x86 microarchitectures:

- **Intel** — top-tier fused ZMM chain kernels are exercised end-to-end from **Rocket Lake (11th-gen, e.g. i7-11700K)** onward. Ice Lake mobile parts carry the required flags but are not the reference host. **Cascade Lake / Cooper Lake and other AVX-512-without-VAES / VBMI SKUs** engage the AVX-512F ARX chain kernels for the BLAKE / SipHash / ChaCha20 family plus the XMM AES-NI 4-lane batched kernels for Areion-SoEM (the fused cascade and the batched SoEM of the general path) and AES-CMAC, take the VEX 8-lane kernels (eight-pixel stride) for AES-ITB-128 and AES-CMAC, and select pixel-encoder Tier A′ (AVX-512F+BW+VL without GFNI/VBMI). **Haswell through Comet Lake** engage the AVX2 4-lane and 8-lane chain kernels (the eight-pixel stride of the pixel pipeline on every family), the AVX2 4-lane interlock rank-mask kernel, the XMM AES-NI 4-lane and 8-lane batched kernels, and pixel-encoder Tier B′ (AVX2 no GFNI).
- **AMD** — top-tier fused ZMM chain kernels engage from **Zen 4 onward** (server-class Zen 4 / Zen 5); pixel encoder runs Tier A (GFNI present). **Zen 3** engages the VAES YMM fused ChainHash cascade kernels for AES-ITB-128 and AES-CMAC (four and eight lanes) and for Areion-SoEM, the VAES YMM per-half permute for Areion-SoEM, the AVX2 four- and eight-lane BLAKE2s / BLAKE3 / SipHash / ChaCha20 fused ChainHash cascade kernels, the AVX2 four-lane BLAKE2b kernels, the AVX2 4-lane interlock rank-mask kernel, and pixel-encoder Tier B′; the pixel pipeline takes the eight-pixel stride on every family. **Zen 1 / Zen 2** carry AES-NI and BMI2 and engage the Interlocked Barrier BMI2 apply kernels, the AVX2 4-lane rank-mask kernel, and the AVX2 and AES-NI fused ChainHash cascade kernels. `PEXT` / `PDEP` are microcode-emulated there, with a latency that grows with the mask popcount; every Interlocked Barrier mask has a fixed popcount (see [HWTHREATS.md](HWTHREATS.md)).
- **Older or narrower x86-64 hosts** — build with `-tags noitbasm` to skip the ITB-native assembly entirely; the upstream primitive libraries' own ASM (`crypto/aes`, `dchest/siphash`, `golang.org/x/crypto`, `zeebo/blake3`) stays engaged. The CGO pixel encoder needs no such tag: on a host without AVX2 it runs its portable C tier, built for baseline x86-64.
- **The `noasm` build tag** — on amd64 the CPU features come from `github.com/klauspost/cpuid/v2`, which reports none under `-tags noasm`; every ITB kernel then takes its scalar path. Output is unchanged, throughput drops.
- **ARM64** — the Areion-SoEM permutation runs through `AESE`/`AESMC` on hosts with the ARM Crypto Extension (`internal/areionasm/areion_arm64.s`), AES-ITB-128 engages the same extension for fused cascade and batch-16 fill (`internal/aesitbasm/`), and NEON fused cascade kernels accelerate the BLAKE / SipHash / ChaCha20 primitives. The Interlocked Barrier unrank runs via the 8-lane NEON kernel (`internal/interlock/interlockasm48_neon_arm64.s`), chunk application accelerates via SVE2 BitPerm (`FEAT_SVE_BitPerm` on Graviton 4 / Neoverse V2) or the batched ARM64 apply kernel, and portable Go fallbacks remain available.
- **Every other Go target** — the pure-Go pipeline via `CGO_ENABLED=0` runs on any GOOS / GOARCH the Go compiler supports; throughput drops but correctness is preserved.
